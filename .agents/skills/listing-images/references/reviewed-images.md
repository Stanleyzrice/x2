# 默认已审图片流程

默认由 Codex 或人建立完整真实看图证据，必要时用已授权 OpenAI Image（图像编辑）修改后加文案；干净原图直接采用，未变的有效证据按第3节复用。取源、规格映射保存、导入、水印、上传和最终审阅均经X2已登记入口。此路径不依赖 Gemini（模型检查）额度，不使用模型报错或生成成功替代审核通过。只有人明确选择时才走 `original` 或 `processed` 其他路径，不能失败后自行降级。

## 1. 复用当前稿并保存完整来源

先核对目标店、指定货源、已有稿、完整来源、实际审图证据、已导入／上传记录及结果未决记录；优先复用当前稿，只续缺项，不重复建稿、不覆盖人工值，不盲目重跑prepare／make／import。商品创建或发布结果未知时先按上架流程查原请求，不重复提交。

尚未保存完整货源与所选规格的未建商品稿，用 `listing make --ids <单稿编号> --prepare-only` 复用采集快照、核价并保存完整详情来源。该入口不下载、筛字、译图、上传图片或调用类目与外部模型；准备成功仍是待图片处理与审阅。已有完整来源直接预览复用；已有已审图片不能用 `prepare-only` 重排覆盖。稿不存在时先按上架流程登记，不能把备选编号直接当稿号。

运行 `listing reviewed-images-preview --id <稿号>`，保留 `expectedScope`（源规格与映射指纹）、全部 `sourceMain`／`sourceDetail` 及数量、`savedSourceShas` 和 `requiredOptions`。完整核对源主图、详情图、所有已选SKU图片及对应证据；未变且符合第3节的证据可复用，首次、新增、改变或有疑点的图片才重新打开及必要对照。若采集不完整、来源错款或所选规格无可靠图片对应，先补齐事实或标待核对；不编造图片映射。确能从已保存源图核实的映射，才按 `make --prepare-only --sku-images` 当前参数正式保存并重新预览，不直改库。

从供货页预览或现成素材识别采用项。保留完整源 URL 清单，未采用的重复场景、其他款、供货宣传按组记过滤依据。只对采用或需要查清的图片用 `image save --url <源URL> --out <本地路径>`。采用项保存文件 SHA256（文件指纹）、实际看图结论、角色及所选 SKU 对应。准备真实详情图，并在图文中保留影响购买判断的材质、工艺、用法和尺寸。源图披露的发货或合规冲突按选品规则处理。

## 2. 只编辑必要内容，再查看真实输出

- 台湾站发布前逐张看主图、详情图、规格图和尺码图。面向买家的简体字都转成台湾繁体，款色、尺寸、件数等短标注也要翻译。可选用信息等效的同款繁体图，或用 OpenAI Image（图片编辑）局部翻译。核对款式、数值、单位和规格对应，保留有效商品介绍。产地推广、厂名地址、供货联系方式等区块局部移除，保留法定标识及必要的商品信息。
- 对实物或包装本体的简体印字，优先用同款同规格、避开字样的真实拍摄角度；必须展示的印字保留原状并在图中加对应的台湾繁体说明。遇到无法忠实处理的图片，先留稿补素材，不能为了翻译改变买家会收到的商品。
- 主图、详情图、规格图和尺码图默认处理可选品牌露出。后加的品牌宣传和 Logo（标志）可局部移除或遮挡。实物或包装带标时优先选用同款、同规格且不露出品牌的真实拍摄角度，必要时在展示图局部遮挡品牌字样，保留原图与内部品牌证据。保留影响购买判断的外观、图案、标签及法定标识；遮挡造成实物误导或缺少必须披露的信息时，换用可准确展示的素材或留稿待确认。
- 无待翻译或待处理文字、地区或品牌露出且款式规格对应的图，实际查看后用 `clean-original`（已审干净原图）。终审仍有漏译或无法对应在售规格的图须记录图片编号与问题，补正后才发布。经过翻译、遮挡或移除的图片按实际处理方式和当前指纹重新审阅。
- 首次采用或修改后的每张编辑图须取得真实输出文件，实际放大查看，并按需要与源图、源SKU对照：款式、花色、造型、尺寸、件数、边缘、实物印字及后加文字。记录源SHA、输出SHA、实际编辑内容和审阅依据；未变的已审输出按第3节复用，不因进入最终审阅而机械再打开一次。不能把返回成功、缩略图或从未打开的生成结果当通过。通用面料、底背、吸水等示意保留供应商示意身份，不能冒充所选款实拍或实测；材质与性能标示不能升级为独立证实。
- 修图失败、漏字、乱码、换款、改写真实印字、遮挡影响商品识别或仍留待处理文字时，保留源文件和失败产物及原因，针对问题做局部修正后重新实审。正在运行的请求先查询／等待原结果，不重复发起；长耗时任务及时报告真实进度。无法修好且没有合规替代来源时标未完成，不传回未处理原图、不删有效介绍来冒充完成。输出若只返回编码文件，可原样落盘保存，不用临时像素处理或外部API脚本绕过正式路径。

## 3. 重复图片与已上传资产的复用

先查本稿现有完整来源、处理文件、真实看图证据和上传记录。复用看图证据须同时满足：原图和采用文件均已实际查看，当前源SHA与采用文件SHA分别对应原证据，处理内容未变，且当前款式、规格、件数及用途适用性未变。全部满足时，不重复下载、编辑或机械逐张重开图片；首次采用、新增、改变、证据缺失或有疑点时才重新实际查看及必要对照。相同URL不保证字节未变，画面相似也不是SHA相同；无法确认上述条件时不能假定可复用。

不同URL但原图SHA完全相同，且上述适用性成立时，可复用同一已审处理文件；每条清单仍保留本条真实源URL／源SHA、采用文件SHA和复用依据，逐一核对当前角色与全选SKU映射。跨商品不能只凭同供应商、相似标题或画面相似套图。处理文件变化后重新审图；实际编辑过的文件始终标 `openai-image`，不能改称 `clean-original`。干净原图继续直接采用原文件，不为形式上的“处理完成”重画。

已在同店上传且处理SHA和当前水印配置匹配的图片，由X2正式导入／上传流程复用持久化记录；不要直接拷贝其他店图片ID或手写上传结果。复用记录仍须符合当前来源与全部已选SKU映射，上传成功不豁免最终审阅。无水印时保留采用文件的字节和格式交X2；Shopee（虾皮）可能另做平台压缩，不宣称远端字节未变化。

## 4. 长图、详情数量与尺寸表

当前主图最多9张、详情图最多12张；详情宽≥700、高≥32、宽高比0.5–32。全部图片须宽高>10且总像素不超过4000万。不能静默截断长图或源详情；按清晰边界形成合规图片并逐张核图。一张源长图可对应多份实际处理文件，每份记录相同源URL／SHA、不同输出SHA、内容范围及承接关系，不漏有效介绍，不伪造另一来源。若现有授权和正式能力无法合规处理，先修能力；不能保全内容或仍超限则标阻塞。不要把整张图压成看不清的缩略图，也不用主图补足详情数量。

尺寸表须对照当前所选源SKU逐行核对名称、数值、单位和对应款式，不从图片视觉或其他商品推算。仅有已核数值而无可直接采用源表时，用 `listing chart-render` 生成台湾繁体预览，核图后按其返回参数调用 `listing size-chart`，保留 `expectedScope` 和逐行原始证据。体重／适穿范围是建议而非成衣实测；单位未知不换算、不补造。鞋款只有原始标示鞋码时使用 `kind: "size-label"`，唯一列单位为 `號`，数值与源SKU标码一致，原适穿或偏小提示按事实保留，不换算脚长、鞋内长或其他鞋码系统。排除与已核源规格冲突的旧建议表，不把不同区间混为一致。

## 5. 完整清单经X2导入和上传

在来源与所选规格稳定后重新读取预览指纹，用 `listing reviewed-images --id <稿号> --manifest -` 从 stdin（标准输入）交 manifest（资产清单）：

```json
{
  "expectedScope": "当前预览的源规格指纹",
  "main": [{"sourceUrl":"源URL","sourceSha256":"源SHA256","path":"本地绝对路径","sha256":"采用文件SHA256","provider":"openai-image或clean-original","evidence":"真实逐图依据"}],
  "detail": [],
  "options": [{"sourceUrl":"源URL","sourceSha256":"源SHA256","path":"本地绝对路径","sha256":"采用文件SHA256","provider":"openai-image或clean-original","evidence":"真实逐图依据","skuIds":["本URL的全部已选源SKU编号"]}]
}
```

以上是结构示意，指纹须为实际64位SHA256，`provider` 实值只能为 `openai-image` 或 `clean-original`；`detail` 填本次实际审阅采用的完整列表，不能照抄示意空数组省略真实详情。`clean-original` 的源SHA和文件SHA必须相同；所有源URL须在本稿保存的货源中。`options` 严格按当前 `requiredOptions` 的原URL分组，`skuIds` 精确覆盖每组全部已选SKU，不漏、不重、不含已排除规格，不能依文件编号或款式名称猜顺序。无可靠映射的缺项保留待核对，不拿其他款顶替。

导入工具核文件 SHA、来源 SHA、尺寸和源规格指纹，再经本店已有水印配置、Shopee 上传及 X2 持久化。导入成功后继续成稿，主图、详情图、规格图角色及全选 SKU 映射在终审时结合清单核对。若上传报错，保留回执，按正式记录只续缺项。

随后 `listing make --ids <稿号> --image-mode reviewed` 沿用已导入图与原规格，续补空白类目、属性和备货天数，不再筛字、译图或重排规格。需改变来源、所选规格或图映射时重新预览、核图和导入，不套旧指纹。

## 6. 串行保存、最终指纹审阅与发布读回

同一稿按“来源／规格准备 → 图片导入上传 → reviewed续做及文案／经营参数保存 → 最终预览审阅 → 发布与读回”依次执行，只续未完成环节，前一步完成并读回后再做依赖步骤；不要在上传过程中改稿或并发保存文案、经营参数。不同稿可并行做本地资料、看图和编辑，但共享浏览器的切店、导航、刷新、上传与发布由同一执行者通过单队列串行操作；不在另一任务上传中切店、导航或刷新，不直接操纵页面绕过登记工具。

文案在 `listing text` 保存。稿件齐备后运行 `listing review-preview --id <稿号>`，对照实际主图、详情图、规格图、尺码图、采用文件的 SHA-256（文件指纹）及适用 SKU（规格货号）。文件及适用规格未变，且当前规则下有已保存的语言结论时直接复用。新增、变化或有疑点的成图逐张看清楚，并与供货原图核对。按[上架终审](../../../../skills/listing/references/workflow.md)填写逐图语言结论，再交给 `listing review`。回执的 `languagePassed` 表明当前成图通过语言关卡。尺码图生成失败后改用供货原图时，同样审阅该最终文件。

每张图在 `--images` 的相应条目中提交 `language`，包含预览对应的 `sha256`、实际判定依据 `evidence` 及 `state`。无中文为 `no-chinese`，面向买家的文字已是台湾繁体为 `traditional`，必须呈现的真实实物简体印字为 `printed-with-note`，此时 `note` 是说明原印字的繁体文字，并要在最终描述中实际出现。存疑用 `pending-check`，漏译或错译用 `needs-correction`。已有结论只有在图片指纹、适用规格及规则版本一致时有效。终审发现待确认或待修正的图，修正后再发布或替换。

`expectedScope` 保护源规格和映射，`expectedKey` 绑定最终商品内容。文案变化时重新审文案及受影响的图文一致性；图片／顺序、所选规格或映射变化时核对改变部分及完整映射，必要时重新看图。随后以当前预览key保存完整结论，不能继续用旧指纹或宣称旧审阅记录直接有效；未变图片的有效看图证据仍可复用。明确审阅与原模型审阅经过同一上架门槛，如实显示 `codex-visual` 或 `human`，不称Gemini已完成。图片实审不代替 selection（选品）、定价、类目和物流规则；疑点、缺项及工具未完成项留待核对。本流程不推广个别批次的尺寸或SKU例外、竞品特批和经营参数。

发布仍经原有 `listing publish` 授权、写入确认、首次试单、建品核对、上架及在售读回流程；结果未知先查原请求，不重发。工具、上传服务或图片入口不可用时，先按项目能力修复正式入口再继续，不换未登记上传路径、不直调内部函数／网站接口、不直写业务库或Gemini缓存；修复后仍不能完成则明确报告未完成原因，不能以原文原图快捷上架替代本流程。
