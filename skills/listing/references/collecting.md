# 人工采集备选区

本轮仅接入1688。在 Ego（浏览器）通过已有 CDP（浏览器调试协议）连接打开独立采购标签页；图片悬停可单件加入备选或采集当前列表页，包含滚动加载的商品，不自动翻页。采集快照保存主图、SKU（商品规格）原编号和原值、规格图、详情文字与详情图；不翻译、不做OCR（图片文字识别）。重复商品不另建一份，失败快照可由下一次完整采集修复，不能覆盖已发布或结果未知的内容。

人工操作留在首页、搜索结果或商品列表：悬停卡片图片即出现「加入备选 / 采集当前页全部」，无需点进详情。从采集页打开的搜索标签沿用同一会话和队列；整页采集只处理发起操作的列表，不混入其他标签。完整规格与详情仅在后台自有标签读取，不激活该标签、不改变当前列表。采集控件复用现有 shadcn/ui（界面组件库），默认收起为可拖动悬浮球，点击才展开进度和操作，避免遮挡平台导航。

单件点击立即显示排队反馈，可以继续选择下一件；后台按点击顺序采集，执行中或等待中的同一商品不重复排队。「已排队」只表示请求待处理，保存成功后才算加入备选。单件队列允许继续浏览同平台的其他列表；整页采集仍限定发起时的当前页。停止会取消等待项，当前商品处理结束后保留真实结果；平台验证或连接中断时明确反馈，不自动重启已取消的任务。

备选区可单件删除或勾选后批量删除，只处理明确选中的编号。删除将商品移出共享备选区，保留来源快照、商品稿和上架记录，不执行外站下架；任一店铺存在进行中或结果未决的发布时先核对。用户重新指定该商品时，可用 `listing source-restore --link '<原1688链接>'` 恢复同一来源并续原稿。普通采集和策略运行继续保留删除状态。

`listing sources --shop <店>` 查看备选；`listing source-detail --shop <店> --source-id <备选编号>` 看原始内容。Agent默认按[通用上架流程](../SKILL.md)及[操作顺序](workflow.md)复用关联稿，先 `make --prepare-only` 保存来源与核价，再处理图片并实审。`listing source-prepare --shop <店> --source-ids <备选编号>` 属于人工原文原图准备，会进入图片上传，不是无上传的资料准备入口。已有商品稿按原流程复用，不改其人工字段；备选区不创建平行上架逻辑。缺失库存、采购价、重量、国内运费、必填类目属性或备货天数时保留未知并按主流程补充，不编零值，也不静默截断超出平台限制的图片和规格名。人工补充值独立保存，原始快照保持原样。

备选区的「全部上架」「上架选中」沿用既有店铺定价、类目范围及物流规则；按钮先准备稿件，再冻结当前可上架子集及指纹，缺项商品留在区内。需要处理品牌露出的商品走已审图片流程。用户点击批准的是本次原文原图内容，不冒充人工逐图审阅或Gemini检查；仅标记人工采集来源且图片模式为original（原图）的同一指纹可使用这份批准。普通商品稿的既有审阅门槛不变。建商品、上架和读回仍经原有写入引擎，结果未知先核对，不能重发；页面刷新后按原请求编号恢复结果。

## 导出给 Agent 的上架任务

「导出上架提示词」只读取本次勾选商品、目标店铺及其本地关联进度，生成以下模板，不准备商品稿、不上传图片、不执行发布，也不自动启动 Agent。打开预览时固定本次清单和店铺；复制和下载内容相同，导出后保留原勾选。附导出时间、稿号、商品号、图片模式、来源保存情况及独立的未决写入编号，帮助定位续做；这是本地快照，不代表实时在售、图片已审或发布已获批准。执行前仍读当前状态与指纹。商品标题、详情、原跳转地址、错误原文及确认令牌不拼入任务指令。规则继续在现有流程文件维护，模板不另存一套定价参数或历史批次特例。

预览文字允许用户补充本批尺寸、排除款式等要求；复制和下载均使用当前编辑内容，关闭弹窗后不保存这份临时编辑，不改数据库或店铺规则。空白内容不可复制或下载。只有用户将任务交给Agent执行后才按其明确要求及项目写入流程处理；打开预览或编辑文字本身不触发上架。
