# 审稿

跟运营只提会出事的：IP、品牌、违规话术、意思译反、规格、类目、价格不对。别的图的问题在商品稿的「说明」里，不逐条转述。

## 开审稿视图

`x2 page create` 开一页，`x2 page push` 放上去：

```json
{ "component": "datagrid", "props": { "title": "审稿", "table": "listings", "filter": { "step": ["待批准", "待补充"] }, "sort": [{ "col": "id" }], "layout": "cards" } }
```

只给这几份就在 `filter` 里加 `"id": ["3", "5"]`。把地址告诉运营，她在右边看标题、主图、详情图、规格和价格、规格图。运营自己贴货源：放 `{ "table": "listings", "group": { "col": "step" } }`，右上角有表单「添加货源」。

## 她做的、你记的

- **删图**：不要的主图、详情图她点「删」。删了图要再查一次，`x2 status` 会说。
- **要回 x2 去掉的图**：说明里写着「x2 已去掉」（例 详情图 3）。她说要用，`listing keep` 放回来（记进「保留的图」）。
- **去规格**：她说哪个规格不要（例 接不了的「定製」），`listing drop` 去掉整个选项（两层有同名的写「层名:选项名」）或单个规格（货号）。去掉单个规格让两层组合不齐时它不做：要么去掉整个选项，要么她说了才合成一层「款式」。去完再 `listing audit`。
- **放弃**：她说哪份不上了，`listing cancel` 替她勾「放弃」。已经建了商品的不是放弃，告诉她要下架。
- **备注**：她要改的写在「备注」里，`todo` 的「备注」给出她新写、改过的原文。照着做（改文案、去规格、放回图……，要她定的问她），做完 `listing noted` 记下看过。她的备注你不改。
