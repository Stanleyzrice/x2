读者是推进上品的 agent。命令在 x2 仓库根目录运行：`node bin/x2.ts <命令>`（下面简写成 `x2`），加 `--json` 读结果。跟运营说起商品稿用「简称（店铺）」（命令输出里就是这样写的），别只说编号。

## 步骤

1. **`x2 status --json`**：看 `todo` 里的「做商品稿」「估重量、国内运费」「写文案」「Gemini 文字检查」「备注」，`human` 里类别是「商品稿」的（待补充的、待批准的）。`x2 listing list` 列出每份商品稿的当前步骤。
2. **添加货源**：运营给了 1688 链接，`x2 listing add --shop <店> --links <链接,…>`（店是 `ni1206` 或 `cheeroutdoor`）；按策略选出来的加 `--strategy <名字> --why "选品理由" --evidence "依据"`（先 `x2 selection strategy-add` 记下这个策略）：理由一两句说为什么选它，依据写数据（台湾的热搜词和搜索量、竞品价格和销量、1688 月销、报价），x2 同时记下当时的策略版本和在用的选品规矩（`x2 selection rule-list`）。几个链接一起加的理由是同一份，理由不一样就分开加。改策略用 `x2 selection strategy-set --name <名字> … --why "为什么改"`；已经加进来、没写理由的用 `x2 listing why --id <商品稿> --why … --evidence …` 补记。选品时先报价：`x2 listing quote --link <链接> [--shop 店]` 看售价区间、每个规格的价格和重量、服务、起订量（1688 没给的重量按 1 kg、读不到的国内运费按 10 元估，会写出来），价格合适再添加。两家店各卖各的：同一个货源别两家都上，除非运营说。运营也可以自己贴：开会话放「商品稿」的「全部」视图（`{ "component": "datagrid", "props": { "table": "listings", "view": "全部" } }`），她用表单「添加货源」。
3. **做商品稿**：`x2 listing make [--ids <商品稿,…>]`（几份同时做，默认 3 份，`--jobs N` 改）。每张图 Gemini 看一次（几张同时问），有简体字的交象寄译成繁体（收费，一张约 0.025 元），译好的再查一遍（还有简体字、商品上的字被改了的不用），加本店水印，传 Shopee（碰浏览器的一份一份排队）；再定类目、属性、备货天数，按店铺设置核价。做完它会说缺什么：
   - 1688 没给的重量、读不到的国内运费由你估（`todo` 的「估重量、国内运费」带着 1688 的标题和每个规格）：`x2 listing estimate --id <商品稿> --weight <kg> --freight <元/件>`，只写缺的。重量往重了估，轻的写 1 kg；国内运费往高了估：留出利润。它只填空着的（人填过的不动），写完马上重新核价。
   - 别的是待补充（类目不在本店范围、要填字的属性……）：请运营处理，处理好了再 `x2 listing make`。类目不在本店范围的，她在「店铺设置」里加上这个类目，或者定一个允许的类目：她定了，`x2 listing category --id <商品稿> --category <叶子类目 id>`（类目 id 在 `x2 shopee category-tree` 里找），再 `x2 listing make`；以后做商品稿照用她定的类目。
4. **写文案**（标题、描述、规格名、简称）：能开 subagent 就交给 `listing-copy`（给它商品稿编号、选品时找到的热搜词和这是什么东西；选品时看图、看竞品得来的材质、配件、功能、数量不当事实给它，`listing show` 里没有的不写，免得写成不实宣传；它读规矩、写、交给 x2、照 Gemini 文字检查挑出的问题改，回报结果），主对话不用装每份商品稿的事实。自己写的话：`x2 listing show --id <商品稿>` 看事实（货源标题、规格的每层和每个选项、类目、属性、服务），照 `.claude/agents/listing-copy.md` 的「文案的规矩」写台湾繁体的标题、描述和规格名，要点：
   - 标题 10–60 字（含空格），核心品名放最前：「核心品名＋关键差异＋用途场景＋款式选择」，资料够时 55–60 字；
   - 描述按「商品介紹、規格選擇、使用提醒」分段，最多 3000 字；
   - 只用给的事实：不编造品牌、材质、认证、功能、产地、赠品、热销、免运、发货时效；不写价格；随机款写明随机；不把不同规格的属性写成每件都有；
   - 不写厂家、批发、代发、冲量、定制、爆款这类话；两家店的标题不能一样；
   - 规格名：每层的层名、每个选项的名字，个数、顺序照 show 的 `tiers`；
   - 简称：简体中文，说清楚是哪个，最多 12 字（例 浴水生财猫狗地垫），人和你都用它认商品稿。
   写好用 `x2 listing text --id <商品稿> --title … --description … --tiers '[{ "name": "款式", "options": […] }, …]' --nickname …`（几份一起：`x2 listing text --items - < [{ id, title, description, tiers, nickname }]`）；人在网页上改过的简称它不改。有一样不对就什么都不存，照它说的改了再交。写完马上 Gemini 文字检查：只提示、不挡，挑出的问题带编号写进商品稿的「说明」。只改它指出的、我们自己写的文案、规格名里的简体字和错字，改一次就停；从图上引出来的意见（图上的字和文案对不上、图上的简体字、措辞）不管，不为它改文案，留在「说明」里。图的 x2 自己处理：印在商品上的字不算问题，详情图、不是封面的主图上后加的文案 x2 去掉。
5. **审稿、批准**：跟运营只提会出事的（IP、品牌、违规话术、意思译反、规格、类目、价格不对），别的图的问题在「说明」里，不逐条转述。开会话放商品稿的审稿视图（`x2 session push --id <会话> --items '<JSON>'`：`{ "component": "datagrid", "props": { "table": "listings", "view": "审稿" } }`；只给这几份加 `"filter": { "id": ["3", "5"] }`），把地址告诉运营，她在右边看：标题、主图、详情图、规格和价格、规格图；不要的主图、详情图点「删」（删了图要再查一次，`x2 status` 会说）；「说明」里有 Gemini 挑出的问题。她说 x2 去掉的哪张图要用（说明里写着「x2 已去掉」，例 详情图 3），`x2 listing keep --id <商品稿> --images "详情图 3"` 放回来（记进「保留的图」）。运营说哪个规格不要（例 接不了的「定製」），`x2 listing drop --id <商品稿> --specs <选项名,…>` 去掉整个选项（两层有同名的写「层名:选项名」，单个规格写货号；去掉单个规格会让两层的组合不齐时它不做，要么去掉整个选项，要么她说了才加 `--merge` 合成一层「款式」），再 `x2 listing audit --ids <商品稿>`。她说哪份不上了，用 `x2 listing cancel --ids <商品稿,…> [--why "原因"]` 替她勾「放弃」；已经建了商品的不是放弃，告诉她要下架。
   - 她要改的写在「备注」里：`todo` 的「备注」给出她新写、改过的备注原文。照着做（改文案、去掉规格、放回图……，要她定的问她），做完 `x2 listing noted --ids <商品稿>` 记下看过；她的备注你不改。
6. **建商品、上架**：她看过、在终端里说批准哪几份，`x2 listing publish --ids <商品稿,…>`（只收待批准、待上架的）：建商品（先建成下架）→ 读回来逐项核对 → 上架 → 读回来在售。把每一行的结果原样告诉她。「被拒」的 Shopee 原因写在说明里：改好了请她看过再说批准。「不一致」是读回来和提交的对不上：商品停在下架，请她到卖家中心看，她说了结果，用 `x2 resolve --id <写入> --status 已核对|被拒`。

## 规矩

- 上哪些货源、批不批准是运营定的；你准备、写文案，不替她定：她说了「批准」才 `x2 listing publish`，说了「放弃」才 `x2 listing cancel`，定了类目才 `x2 listing category`。售价由代码算，你不改；重量、国内运费只估 1688 没给、读不到的（空着的才填）。
- 店铺设置（核价参数、水印、允许的类目、暂停上品）是人定的，人让你改才改。
- 保留的图（`x2 listing keep`）要运营说了才用。
- 退出码 3（没登录、要过滑块、浏览器没连上、店铺被限制）：请运营在浏览器里处理，再重试。退出码 4（结果未知）不重试：`x2 verify` 读回来。
- 命令报错，把原话告诉运营。
