读者是推进订单的 agent。命令在 x2 仓库根目录运行：`node x2.ts <命令>`（下面简写成 `x2`），加 `--json` 读结果。

## 步骤

1. **`x2 status --json`**：看 `human`（人要做的）和 `todo`（你能做的）。按出货期限从近到远跟运营说：几张订单、各自的当前步骤（订单上的 `step`）；快到期的先说。
2. **找货源**（`todo` 里有「找货源」）：照它给的 `tool`、`params` 调：`x2 orders source --items <商品 id,…>`（店里的商品 id）。一个商品只用一个货源：它拿商品图以图搜图（要知虾登录着），看店里卖过的规格在每个货源里有几成配得上：
   - 卖过的规格都配得上、只有它这样：标成明显匹配，人同意加购时一起定下，不用另外问人；
   - 拿不准的：写进「货源」，`x2 status` 提醒「选货源」。开会话放「货源」表（`x2 session push --id <会话> --items '<JSON>'`：`{ "component": "datagrid", "props": { "table": "sources", "filter": { "item_id": ["<商品 id>"] } } }`），把地址告诉运营，请她勾「选用」（按店里的商品分组，一组里没勾的就是还没选）。她贴了 1688 链接，用 `x2 orders source --items <商品 id> --url <链接>`。
   不替运营选。货源定了、店里某个规格按名字配不上，`x2 status` 会提醒「规格不匹配」，详情里有货源里最像的几个规格：请她定哪个配哪个（在会话里「货源」那一行的「规格例外」里写，或者告诉你）。她在终端里说了，你用 `x2 orders spec --item <商品 id> --spec "店里的规格名 = 货源的规格名"` 记下；她没说就不写，不替她猜。
3. **加购**（`todo` 里有「加购」）：那一项写着工具 `orders.cart` 和参数（`params.items`）。给运营看：每一项是哪个货源、货源的哪个规格、几件、哪几张订单，`newSources` 不空的是这次一起定下的货源。她在终端里同意了，把 `params.items` 原样交给 `x2 orders cart --items -`（JSON 从 stdin 读），把每一行的结果原样告诉她。
4. **付款**：人在「付款」那一条提醒写着的 1688 账号的购物车里付款。「不该买」的（订单已取消、已打包）提醒她付款前删掉。她说「我付好了」：运行 `x2 status`（现读购物车和采购单），说哪几张订单付了、寄到哪。
5. **预报**（`todo` 里有「预报」）：同第 3 步（工具 `orders.forecast`），她同意了把 `params.orders` 交给 `x2 orders forecast --orders -`。寄到我们这里的报海快、无单号；寄到 chanboss 的等 1688 发货、有了快递单号才会出现。预报还没在真订单上跑过：它会说要 `--try`。第一次和运营约好一张单，一起跑 `x2 orders forecast --orders - --try`，跑完请她在 chanboss 上看一眼对不对。
6. **打包、快到期、取消、问题单**：都是 `human` 里人要做的。照那一条的详情告诉运营（打包：哪张订单装什么，在 chanboss 上打 SKU 拣货单；取消：购物车里删什么、货退款还是退回卖家、台湾仓的货 30 天内用掉）。x2 看不到结果的（合并、台湾仓……），她说做完了，用 `x2 handled --keys <key>` 记下（key 在 `human` 里），不再提醒。取消的订单在 chanboss 上的预报不重要，不用请人去取消。

## 异常

x2 看得到结果的，处理完就不再提醒；看不到的，人说做完了用 `x2 handled --keys <key>` 记下。

- 订单在 chanboss 里查不到：请运营在 chanboss 订单页点「同步订单」，让它从 Shopee 重新拉。
- 1688 付款 48 小时还没发货（提醒「未发货」）：请运营催卖家；催不动就退款换一家，x2 会重新准备加购。采购单关闭、退款成功的，那几件不算付过，x2 也会重新准备加购。
- 外部采购（人直接在 1688 上买的）：不用做，x2 算付过了；x2 给它加进购物车的那一份标「不该买」，付款前删掉。
- 错货、少件、损坏：开会话放「到货问题」表（`{ "component": "datagrid", "props": { "table": "arrival_issues" } }`），请打包的人用表单「上报到货问题」填；人找卖家退换或重新采购，处理完勾「已处理」。没处理完之前 x2 不提醒打包。
- 买家取消：看货走到了哪。在购物车里的删掉；付了款 1688 没发货的申请退款；发了货的退回卖家（退款、退货的进度 x2 读得到）；在 chanboss 仓库的合并给新订单或退回卖家；到了台湾的在 chanboss 台湾仓上架、30 天内给别的订单用。x2 看不到的那几种，人说做完了 `x2 handled`。

## 规矩

- 改站点只经写工具 `x2 orders cart`、`x2 orders forecast`（运营在终端里同意了）；不自己发请求。它们只收检查算出来该做的：它说「现在不该……」时，先 `x2 status` 看为什么。
- 结果未知（退出码 4）不重试：`x2 verify` 读回来；还核不清的，请运营去站点上看，她说了结果，用 `x2 resolve --id <写入> --status 已核对|被拒`。
- 退出码 3（没登录、要过滑块、浏览器没连上）：请运营在浏览器里处理，再重试。
- 命令报错，把原话告诉运营，不自己改库里的数据。
