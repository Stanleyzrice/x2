# 上品

读者是推进上品的人和 agent。这份讲一个货源怎样变成一家店在售的商品：每一步怎样算做完、谁做、收件箱里写什么。x2 怎么一轮一轮推进在 [loop.md](loop.md)，词在 [glossary.md](glossary.md)。

## 怎样工作

**一个货源 × 一家店 = 一份商品稿。** 两家店各卖各的。x2 做能自动做的（读货源、规格和价格、图、类目属性），agent 写文案，人在 NocoDB 里审稿、在收件箱里批准，`x2 run` 建商品、读回来核对、上架。

```
要上的货源 → x2 做商品稿 → agent 写文案 → 台湾成品审核 → 人审稿、批准 → 建商品（下架）→ 读回来核对 → 上架
```

上哪些货源：人贴链接，或者 agent 按策略选（见「策略」）。

## 每一步怎样算做完

| 一步 | 怎样算做完 | 谁 | 收件箱 / agent 要做的 |
|---|---|---|---|
| 要上的货源 | 「商品稿」里有这一行：哪家店、哪个货源、哪个策略 | 人（NocoDB 表单，或在终端里说）、agent | — |
| 读货源 | 货源快照：规格（名字、价格、库存、重量）、主图、规格图、详情图、服务（一件代发、包邮、48 小时发货）、起订量 | x2 | agent：做商品稿 |
| 类目 | Shopee 推荐的叶子类目（标题加一张已传的图），在本店允许的类目里；备货天数取这个类目的上限 | x2；不在范围的给人 | 要人补：类目 |
| 属性 | 类目的必填属性都有值，值一字不差取自属性树 | x2 按规则挑；要填字的给人 | 要人补：属性 |
| 重量 | 每个规格有重量（1688 的运费重量） | x2；1688 没给的人填 | 要人补：重量 |
| 国内运费 | 货源包邮算 0；不包邮的人填，不当 0 | x2；人 | 要人补：国内运费 |
| 规格和价格 | 排成 Shopee 的规格（最多两层、最多 50 个、最高价不超过最低价 5 倍），每个规格按店铺设置核价 | x2 | — |
| 图 | 主图、详情图、规格图都过了筛字、译图、水印、看成品，传到 Shopee 有图片 id | x2 | 要人补：图 |
| 文案 | 繁体标题 10–60 字、描述 3–3000 字，照「文案」的规矩 | agent | agent：写文案 |
| 台湾成品审核 | Gemini 看成品图和文案，没挑出简体字、错字、误译 | x2 | 没过：文案的 agent 改，图的人删 |
| 审稿、批准 | 人在 NocoDB「审稿」里看过（可以改字、删图），在收件箱勾「批准」 | 人 | 批准：上架 N 个商品稿 |
| 建商品 | Shopee 上有这个商品（下架），读回来和提交的一致 | `x2 run` | — |
| 上架 | 在售 | `x2 run`（同一批，建好了接着上架） | — |

做完 = 这份商品稿在售。批准以后人又改了商品稿：那一批不做，重新批准。

## 规格

- 规格名、选项名转成台湾繁体（OpenCC s2twp，带台湾用词）。
- 只留各规格之间取值不同的那几层。两层而且组合齐全（每个颜色都有每个尺寸）才留两层，不然合成一层「款式」，各层的选项名连起来。
- 层名最多 14 字、选项名最多 20 字，重名的加「-2」「-3」。尺寸类的层只留字母码（S、M、L、XL、2XL……）。
- 规格图只挂在第一层的选项上；同一选项下规格图不一样就报错。
- 每个规格的货号 `sku` = `LT<货源 id>-<1688 规格 id>`（最多 40 字），订单靠它连回 1688 的规格。
- 只有一个规格的商品：单层、空名字。
- 1688 没库存的规格不上。库存取 1688 现在的库存和店铺设置的库存上限里小的。

## 核价

每个规格一个售价：同时满足「毛利率 ≥ 最低毛利率」和「毛利 ≥ 最低毛利」的最小整数售价（台币）。没有倍率、没有尾数 9。参数在「店铺设置」里，一家店一行。

```
运费（元）= 重量（按 0.01 kg 取整）× 每公斤运费 + 贴单费
到岸成本（台币）=（1688 价 + 国内运费 + 运费）× 汇率
平台进账 = 售价 − 成交手续费 − 预售服务费 − 金流费 − 虾币回馈 − 免运方案费（各自四舍五入；免运方案费有每单最低）+ 运费净额
毛利 = 平台进账 − 到岸成本 − 售价 × 退货损耗
毛利率 = 毛利 ÷ 平台进账
```

| 参数 | ni1206 | cheeroutdoor |
|---|---|---|
| 汇率（台币 / 元） | 4.4 | 4.4 |
| 每公斤运费（元，海快） | 10.8 | 10.8 |
| 贴单费（元 / 单） | 1.5 | 1.5 |
| 退货损耗（按售价） | 3% | 3% |
| 最低毛利率（按进账） | 25% | 25% |
| 最低毛利（元） | 8 | 8 |
| 成交手续费 | 6% | 6% |
| 预售服务费 | 3% | 3% |
| 金流费 | 2.5% | 2.5% |
| 虾币回馈 | 0 | 1.5% |
| 免运方案费 | 6%，每单最低 NT$60 | 6% |

例：cheeroutdoor，1688 价 ¥19.9、1.6 kg、包邮 → NT$295。建商品前用现在的参数再核一次：改了汇率、费率，不够价的商品稿会被挡下来重做。

## 图

```
原图 → 筛字（Gemini）→ d 删；m 送象寄译成繁体；p、n 照用；r 再问一次有没有后加的简体字，有就译
     → 本店水印 → 看成品（Gemini：水印看得见、没有供应商痕迹、看得清）→ 传 Shopee → 图片 id
```

- 筛字：d 是供应商痕迹（工厂直供、批发、联系方式、二维码、人民币低价……）；r 是品牌、IP、看不清；m 是后加的营销、说明文字；p 是产品本体上印的字；n 是没字。
- 一张图的身份是字节的 sha256：1688 的地址带缓存参数，按地址认会重复付钱。
- 占位图（1×1）、太小的图先按尺寸剔掉。详情图宽 ≥ 700、高 ≥ 32。主图最多 9 张，第一张是封面；详情图最多 12 张。
- 象寄：一批最多 5 张，交一次收一次钱（约 0.025 元一张），记成写入「译图」（不用批准）。先记意图再交；象寄说译不成的那张不用；没拿到答复的结果未知，不重交，收件箱请人核对。译好的图存进库（象寄的地址会失效）。p 类不送：象寄会把表盘、铭牌上的字涂坏。
- 水印：每家店一套（文字、字号、不透明度、位置），在浏览器里画，从原图或译图开始画，不叠；字带白色描边，深色图上也看得见。两家店的封面因此不一样（Shopee：跨店标题和封面一样会禁卖）。
- 台湾成品审核：Gemini 一次看 4 张成品，加标题、描述、规格，挑简体字、错字、误译；挑出任何问题就挡下。标题、图变了要再审。

## 文案

agent 写（Claude Code 里交给 subagent `listing-copy`，见 `.claude/agents/listing-copy.md`）：

- 台湾繁体、台湾用词，只用货源给的事实（`x2 listing show`）。
- 标题：核心品名放最前，「核心品名＋关键差异＋用途场景＋款式选择」；资料够时 55–60 字，最多 60 字（含空格）。手动和自动都有的写「手動／自動可選」；不逐个罗列花色；不写工厂型号；不为凑字数混进不相干的用途。
- 不写厂家、批发、代发、冲量、定制、爆款这类话；不编造热销、现货、免运、品牌、认证、材质、功能、赠品、产地、疗效、发货时效。
- 描述按「商品介紹、規格選擇、使用提醒」分段，最多 3000 字；不写价格；随机款写明随机；不把不同规格的属性写成每件都有；只是估的重量不写成商品净重。
- 两家店各写各的，标题不能一样。

## 建商品、上架

- 在卖家中心的页面里发 `create_product_info`（从别处发会被反爬拒）。`product_info` 的格式在 `src/listing/product.ts`。物流渠道照卖家中心的样子：有尺寸的渠道 `sizeid` 是 1，填错回 1000100256。
- 先建成下架，读回来逐项核对（标题、货号、类目、重量、主图、尺码表、备货天数、物流、描述里的字和图、每个规格的选项、价格、库存），对上了才上架；上架以后读回来状态是在售才算。对不上就停在下架，给人看。
- 1000100256 是字段校验失败（缺必填属性、详情图尺寸、缺尺码表……），不是重复：响应里全部的 `Rule Type` 写进写入的原因。
- 建商品结果未知：不重发，按货号在全部商品里找；找不到请人到卖家中心看。
- 店铺被限制（新增商品页跳到「權限不足 / 賣場遷移中」）：停下，要人处理。人可以在店铺设置里写「暂停上品」。

建商品、上架还没在真站点跑过：第一次和人约好一个货源，`x2 run --try 建商品,上架` 一起跑，跑完在卖家中心看一眼。

## 表

| 表 | 一行是 | 主要的列 |
|---|---|---|
| 店铺设置 `shop_settings` | 一家店 | 核价参数；预售、起购量、库存上限、物流渠道；允许的类目；水印；暂停上品。在 NocoDB 里改，库里有范围约束（比例在 0–1、汇率大于 0），填错存不进 |
| 商品稿 `listings` | 一个货源 × 一家店 | 店、货源、策略；货源快照；类目、属性、备货天数；规格和价格；图和给人看的主图、详情图（NocoDB 附件）、人删掉的图；标题、描述；人填的（重量、国内运费、不上了、备注）；卡在哪一步、要人补的、台湾审核；建好以后的商品 id、上架时间 |
| 图 `images`、`shop_images` | 一张图（字节的 sha256） | 来源、宽高、筛字和看成品的结果、译图的字节；传到哪家店、图片 id |

卡在哪一步：要做商品稿、要人补、等文案、等台湾审核、台湾审核没过、等批准、建商品中、建好了没上架、已上架、暂停上品、不上了。

收件箱的 key：`listing-fix:<商品稿>`（要人补的）、`listing-image:<商品稿>`（台湾审核挑出图的问题）；批准是 `approve:<批次>`。agent 要做的在 `x2 status --json` 的 todo：做商品稿、写文案、台湾审核、上架（现成的一批写入）。写入的防重复 key：`xiangji:<图的 sha256…>`、`create:<店>:<货号>`、`live:<店>:<货号>`。

NocoDB：「商品稿」的视图「全部」、「审稿」（画廊，封面是主图）、「卡在哪一步」（看板）、「要上的货源」（表单：选店、贴 1688 链接）；「店铺设置」在「订单设置」后面。主图、详情图是 NocoDB 的附件，只放 Shopee 的图片地址（公开的，NocoDB 直接显示）：人删了哪张附件，x2 下一轮记进「删掉的图」，以后都不用它（要再审一次）。

## 命令

```
x2 listing add <店> <1688 链接…> [--strategy 名字]   要上的货源
x2 listing make [商品稿…]                           做商品稿（不给就做所有还没做好的；人补完了再跑一次，做过的不重做）
x2 listing show <商品稿>                            写文案要用的事实
x2 listing text <商品稿> --title … --description …  写标题和描述，写完马上台湾成品审核
x2 listing audit [商品稿…]                          台湾成品审核
x2 listing list                                    每份商品稿卡在哪一步
```

建商品、上架走 `x2 propose` → 批准 → `x2 run`。

## 策略

选品由 agent 定策略、做实验（explore / exploit）。「策略」表一行一个：押什么、怎么选、试验中 / 在用 / 停了。每份商品稿记下它从哪个策略来（人贴的是「人选」）。

```
x2 strategy add <名字> --bet "押什么" --how "怎么选"
x2 strategy set <名字> --status 在用|停了|试验中 [--note …]
x2 strategy list                      每个策略出了几份商品稿、上架了几个
```

还没做的：按策略汇总上出来的商品的曝光、点击、加购、订单、毛利（等有商品上架了，照 Shopee 的商品表现做）。
