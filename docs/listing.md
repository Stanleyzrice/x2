# 上品

读者是推进上品的人和 agent。这份讲一个货源怎样变成一家店在售的商品：每一步怎样算做完、谁做、收件箱里写什么。x2 怎么一轮一轮推进在 [loop.md](loop.md)，词在 [glossary.md](glossary.md)。

## 怎样工作

**一个货源 × 一家店 = 一份商品稿。** 两家店各卖各的。x2 做能自动做的（读货源、规格和价格、图、类目属性），agent 写文案，人在网页「商品稿」里审稿、一份一份勾「批准上架」，`x2 run` 建商品、读回来核对、上架。

```
添加货源 → x2 做商品稿 → agent 写文案 → Gemini 文字检查 → 人审稿、勾「批准上架」→ 建商品（下架）→ 读回来核对 → 上架
```

上哪些货源：人贴链接，或者 agent 按策略选（见「策略」）。

## 每一步怎样算做完

| 一步 | 怎样算做完 | 谁 | 收件箱 / agent 要做的 |
|---|---|---|---|
| 添加货源 | 「商品稿」里有这一行：哪家店、哪个货源、哪个策略；agent 按策略选的还有选品理由、依据、选品快照 | 人（网页的表单「添加货源」，或在终端里说）、agent | — |
| 读货源 | 货源快照：规格（名字、价格、库存、重量）、主图、规格图、详情图、服务（一件代发、包邮、48 小时发货）、起订量 | x2 | agent：做商品稿 |
| 类目 | Shopee 推荐的叶子类目（标题加一张已传的图），或人定的类目；在本店允许的类目里；备货天数取这个类目的上限 | x2；推荐的不对、不在范围的人定（agent 用 `x2 listing category` 写，做商品稿不再问推荐） | 待补充：类目 |
| 属性 | 类目的必填属性都有值，值一字不差取自属性树 | x2 按规则挑；要填字的给人 | 待补充：属性 |
| 重量 | 每个规格有重量：1688 给的（运费重量；小于 20 克的当作没给）；没给的用「重量」：agent 往重了估（轻的写 1 kg），留出利润，人可以改 | x2；agent 估 | agent：估重量、国内运费 |
| 国内运费 | 包邮算 0；不包邮的按 1688 页面上寄到我们这里买 1 件的运费算（「运费¥8起」）；读不到的用「国内运费」：agent 往高了估，不当 0，人可以改 | x2；agent 估 | agent：估重量、国内运费 |
| 规格和价格 | 排成 Shopee 的规格存进商品稿（层和规格，见「规格」），每个规格按店铺设置核价 | x2 | — |
| 图 | 主图、详情图、规格图都过了筛字、译图、译图检查、水印，传到 Shopee 有图片 id | x2 | 待补充：图 |
| 文案 | 繁体标题 10–60 字、描述 3–3000 字、规格名，照「文案」的规矩 | agent | agent：写文案 |
| Gemini 文字检查 | 查过现在的文案和图（只提示、不挡）：挑出的问题带编号写进「说明」；详情图、不是封面的主图上后加的文案 x2 去掉 | x2；写文案的 agent 只改自己文案里的简体字、错字，改一次 | agent：Gemini 文字检查 |
| 审稿、批准 | 人在网页「商品稿」的「审稿」里看过（可以改字、删图，看「说明」里 Gemini 挑出的问题，在「备注」里写要求），勾了「批准上架」，勾的时候的内容没变 | 人；agent 照备注做 | 待批准：<店> N 个商品稿；agent：备注 |
| 建商品 | Shopee 上有这个商品（下架），读回来和提交的一致 | `x2 run` | — |
| 上架 | 在售 | `x2 run`（同一批，建好了接着上架） | agent：上架（`x2 run`） |

做完 = 这份商品稿在售。

**批准上架**：一份商品稿一个勾，人在网页上一份一份勾（人在终端里说「批准」，agent 用 `x2 listing approve` 勾同一个勾）。只有待批准、待上架的勾了算数。勾的时候库里记下内容（要建的商品 product_info 的 hash，和建商品时核对的是同一个）；`x2 status`、`x2 run` 重算时内容对不上（改了标题、描述、规格、价格、图、类目……，或者又要重做、再查）就去掉勾，说明里写为什么，人看过再勾。`x2 run` 只做勾着、内容没变的：一份商品稿一批写入（建商品、上架，已批准），防重复的 key 照旧。建商品、上架被拒或没执行的也去掉勾，Shopee 的原因写进说明：改好了再勾。

**备注**：人在商品稿的「备注」里写给 agent 的要求（例 标题别写「成人」、不要定製款）。`x2 status --json` 的 todo「备注」给出上次 agent 看过以后人新写、改过的备注和原文；agent 照做，做完 `x2 listing noted <商品稿>` 记下看过的备注原文；备注再改又出来。人写的备注 agent 不改。

**放弃**：不上这个货源，人在商品稿上勾「放弃」（人在终端里说「放弃」，agent 用 `x2 listing cancel` 勾同一个勾）：当前步骤是「已放弃」，x2 不再做它；还没提交的建商品、上架 `x2 run` 标成未执行（不用等浏览器）。已经建了商品的不是放弃，是下架；建商品结果未知的先核清。

## 规格

商品稿里存着 Shopee 要的规格：层（最多两层，例 款式、尺寸）、每层的选项、每个规格（货号、1688 的规格 id、每层一个选项、进价、库存、重量、售价），层和规格存在一起。做商品稿时从货源生成，以后都改它；核价、建商品、Gemini 文字检查、「规格和价格」都只读这一份。

- 生成：1688 有货的、没移除的规格 → 只留各规格之间取值不同的层 → 两层而且组合齐全（每个款式都有每个尺寸）留两层，不然合成一层「款式」（一个组合一个选项）→ 起名字 → 核价。选项照 1688 列的顺序。
- 认规格靠 1688 的规格 id 和原值：每层记着 1688 的层名，每个选项记着 1688 的原值（转繁体前的原文），名字只是给人看的。改名按第几层第几个选项改，不按字配。
- 名字：x2 先自动起（转台湾繁体，OpenCC s2twp；去掉 emoji 和括号里的短说明；尺寸类的层只留字母码 S、M、L、XL……；最多 20 字，同一层撞名加「-2」「-3」），写文案的 agent 照「文案」改。名字存下来就不再变：重做商品稿时按（1688 层名，原值）把上一版的名字对回去，新出来的选项自动起名字，没货了、移除了的不要。
- 规矩（存之前、建商品前都核一遍，不对的写清楚是哪层哪个选项）：最多两层；层名 1–14 字、选项名 1–20 字；同一层不重名；每个规格每层一个选项，没有两个规格是同一格；两层的组合要齐；每个选项至少有一个规格；最多 50 个规格；最高价不超过最低价 5 倍。
- 规格图挂在第一层的选项上（1688 给第一层取值配的图）；同一个选项下 1688 的图不一样，要人定。
- 每个规格的货号 `sku` = `LT<货源 id>-<1688 规格 id>`（最多 40 字），订单靠它连回 1688 的规格。
- 只有一个规格的商品：单层、空名字，不写规格名。
- 1688 没库存的规格不上。库存取 1688 现在的库存和店铺设置的库存上限里小的。
- 去掉人不要的规格（例 店里接不了的「定製」），人说了才用：`x2 listing drop <商品稿> <选项名…>` 去掉整个选项（它下面的规格都去掉），两层有同名的选项写成「层名:选项名」（例 尺寸:標準）；写货号去掉一个规格。去掉单个规格会让两层的组合不齐时不做：要么去掉整个选项，要么人说了加 `--merge` 合成一层「款式」。去掉的货号记进「已移除的规格」，重做商品稿也不要它；规格变了要再查（Gemini 文字检查）。
- 「规格和价格」按层写，数字由代码算：价格、重量只跟着一层变的，写在那一层的选项后面；两层都影响的，第一层每个选项一行；都一样的写「各」；最后写已移除的。

  ```
  款式（8）：水生財黑貓咪、洗洗睡吧梅棕狗、……
  尺寸（4）：40×60cm NT$133 0.216 kg · 50×80cm NT$155 0.36 kg · 60×90cm NT$176 0.486 kg · 80×120cm NT$253 0.864 kg
  共 32 个规格，库存各 50
  ```

- 规格图：第一层一个选项一张（名字是「规格图：选项名」），网页上只看、不能删；不要的款式告诉 agent 去掉。

## 核价

每个规格一个售价：同时满足「毛利率 ≥ 最低毛利率」和「毛利 ≥ 最低毛利」的最小整数售价（台币）。没有倍率、没有尾数 9。参数在「店铺设置」里，一家店一行。

```
运费（元）= 重量（按 0.01 kg 取整）× 每公斤运费 + 贴单费
到岸成本（台币）=（1688 价 + 国内运费 + 运费）× 汇率
平台进账 = 售价 − 成交手续费 − 预售服务费 − 金流费 − 虾币回馈 − 免运方案费（各自四舍五入；免运方案费有每单最低）+ 运费净额
毛利 = 平台进账 − 到岸成本 − 售价 × 退货损耗
毛利率 = 毛利 ÷ 平台进账
```

| 参数 | ni1206 | cheeroutdoor |
|---|---|---|
| 汇率（台币 / 元） | 4.4 | 4.4 |
| 每公斤运费（元，海快） | 10.8 | 10.8 |
| 贴单费（元 / 单） | 1.5 | 1.5 |
| 退货损耗（按售价） | 3% | 3% |
| 最低毛利率（按进账） | 25% | 25% |
| 最低毛利（元） | 8 | 8 |
| 成交手续费 | 6% | 6% |
| 预售服务费 | 3% | 3% |
| 金流费 | 2.5% | 2.5% |
| 虾币回馈 | 0 | 1.5% |
| 免运方案费 | 6%，每单最低 NT$60 | 6% |

例：cheeroutdoor，1688 价 ¥19.9、1.6 kg、包邮 → NT$295。建商品前用现在的参数再核一次：改了汇率、费率，不够价的商品稿会被挡下来重做。

1688 没给的重量、读不到的国内运费不挡给人：agent 照 1688 的标题和规格估，`x2 listing estimate <商品稿> --weight <kg> --freight <元/件>`，写进「重量」「国内运费」，只填空着的（人填过、改过的不动）。重量往重了估，轻的写 1 kg；国内运费往高了估：估多了售价高一点，估少了亏钱。「重量」「国内运费」一填、一改（agent 估的、人在网页上改的都马上），x2 照货源快照重新核价，不再读 1688。估之前商品稿停在「待做商品稿」（说明写着缺什么），不进收件箱。定不了价的、超过上限的（最高价超过最低价 5 倍、超过 50 个规格）现算，给人。

## 图

```
原图 → 筛字（Gemini）→ d 删；m 送象寄译成繁体；p、n 照用；r 再问一次有没有后加的简体字，有就译
     → 译图检查（Gemini 分两次问）→ 本店水印 → 传 Shopee → 图片 id
```

- 筛字：d 是供应商痕迹（工厂直供、批发、联系方式、二维码、人民币低价……）和写给 1688 买家的说明（售后、退换货、退货运费、定制、色差尺寸的免责「望亲谅解」、「亲」的口吻：译得再好也不该出现在我们的商品里）；r 是品牌、IP、看不清；m 是后加的营销、说明文字；p 是产品本体上印的字；n 是没字。
- 一张图的身份是字节的 sha256：1688 的地址带缓存参数，按地址认会重复付钱。
- 筛字、译图检查问 Gemini 出错（超时……）的那张不用，不挡商品稿；不缓存，下次做商品稿再问。
- 占位图（1×1）、太小的图先按尺寸剔掉。详情图宽 ≥ 700、高 ≥ 32，宽高比在 0.5–32 之间（Shopee 的要求，太长的不用）。主图最多 9 张，第一张是封面；详情图最多 12 张。
- 象寄：一批最多 5 张，交一次收一次钱（约 0.025 元一张），记成写入「译图」（不用批准）。先记意图再交；象寄说译不成的那张不用；没拿到答复的结果未知：不重交，这张先不用（drop 写着是哪个写入），商品稿照样往下走，收件箱请人核对；核清以后再做商品稿就用上（人核对成已核对的，象寄的地址没拿到，再交一次）。译好的图存进库（象寄的地址会失效）。p 类不送：象寄会把表盘、铭牌上的字涂坏。商品上印着简体字的照样上（例 地垫印着「浴水生财」）：图保留原貌，这种字不算问题。
- 译图检查：分两次问 Gemini。译图上后加的文案还有没有简体字（象寄漏译的，和简转繁选错的字，例 易干译成易幹，应为易乾）：只给译图问（两张一起给，模型会把原图的字当成译图上的）；默认模型也分不清繁简，先让它照抄译图上的字，它说的简体字、错字要在抄的字里，再用 OpenCC 核对（真是简体字；真是同一个简体字选错了繁体，不是异体字、不是换了说法）。商品本体上印的字（印在实物表面、跟着实物的形状和材质走的字，例 地垫的印花、瓶身标签；后加的圆圈、方框、色块里的标签不算）有没有被象寄改动（简体改成繁体、涂掉、重画）：给原图和译图一起问。任何一样有，这张不用，后面的图补上来（象寄的接口没有「商品上的字不译」的选项）。
- 水印：每家店一套（文字、字号、不透明度、位置），在浏览器里画，从原图或译图开始画，不叠；字带白色描边，深色图上也看得见。两家店的封面因此不一样（Shopee：跨店标题和封面一样会禁卖）。加了水印不再让 Gemini 看一遍：水印是我们自己画的，供应商痕迹筛字时已经挑过。
- 同时做：每张图照旧单独判，只是不排队。问 Gemini（筛字和它的兜底、追问，译图检查的两问，Gemini 文字检查的每一批和挑出图以后的追问）同时最多 `X2_GEMINI_CONCURRENCY` 个请求（默认 8）；取图（原图、译图）同时最多 `X2_DOWNLOAD_CONCURRENCY` 张（默认 6）；同一张图同时要的只做一次，结果照旧按 sha 缓存。`x2 listing make --jobs N` 几份同时做（默认 3）：问 Gemini、交象寄、取图几份重叠；碰浏览器的（读 1688 货源、加水印、传图、新增商品页、推荐类目、属性、备货天数）在一个 x2 进程里按浏览器排队，一个浏览器同一时刻只做一件（x2 在一个浏览器里每个站点只开一个标签页）；读 1688（货源页、详情图）两次之间隔 3 秒：读得太密 1688 会跳滑块验证。

## 文案

agent 写（Claude Code 里交给 subagent `listing-copy`，见 `.claude/agents/listing-copy.md`）：

- 台湾繁体、台湾用词，只用货源给的事实（`x2 listing show`）。商品名用台湾买家搜的说法：知虾的热搜词里搜得多的那个（例 矽藻土地墊、珪藻土，不是硅藻泥），选品时找到的热搜词一起给写文案的人。
- 标题：核心品名放最前，「核心品名＋关键差异＋用途场景＋款式选择」；资料够时 55–60 字，最多 60 字（含空格）。手动和自动都有的写「手動／自動可選」；不逐个罗列花色；不写工厂型号；不为凑字数混进不相干的用途。
- 不写厂家、批发、代发、冲量、定制、爆款这类话；不编造热销、现货、免运、品牌、认证、材质、功能、赠品、产地、疗效、发货时效。
- 描述按「商品介紹、規格選擇、使用提醒」分段，最多 3000 字；不写价格；随机款写明随机；不把不同规格的属性写成每件都有；只是估的重量不写成商品净重。
- 规格名（层名、选项名；`x2 listing show` 的 tiers，个数、顺序照它）：台湾繁体；只写这一层要分辨的东西，每个选项都一样的字不写（例 尺寸里的材质说明「（升級版矽藻泥）」、每个尺寸都一样的厚度「0.25」）；尺寸写成「60×90cm」，单位写清楚（「60*90cm（升級版矽藻泥）」写成「60×90cm」，「50*80*0.25」写成「50×80cm」）；款式名写清楚是什么（颜色、图案、造型），不编造；选项名最多 20 字，同一层不重名；层名例「款式」「尺寸」「顏色」，最多 14 字。只有一个规格的商品不写规格名。
- 两家店各写各的，标题不能一样。
- 简称：人和 agent 认商品稿用的短名，不上 Shopee。简体中文，说清楚是哪个（品名加上分得开的特点），最多 12 字，例「浴水生财猫狗地垫」「不规则动物地垫」。x2 做商品稿时先填 1688 标题的前 12 个字；写文案的 agent 写标题时一起写，只在空着、还是自动填的那个值时写进去，人在网页上改过的不改。收件箱、`x2 listing list`、批准的标题、命令输出里商品稿都叫「简称（店铺）」，命令要用编号的跟在后面：浴水生财猫狗地垫（cheeroutdoor，#2）。

## Gemini 文字检查

建商品前 Gemini 看一遍文案（标题、描述、规格名）和图，挑简体字、错字、误译。只提示、不挡：查过了，别的都齐了就到「待批准」，人审稿时看。

- 看加水印之前的图：译过的看译图，没译的看原图（水印会挡住字）。一次 4 张，带上文案。按内容缓存：标题、描述、规格名、图变了要再查。
- 挑出的图再问一次字在哪：印在商品上的不算问题；后加的文案，详情图和不是封面的主图 x2 去掉（Pic 的 drop 写「Gemini 文字检查：<问题原文>」，不进已删除的图，网页上标着「x2 去掉」），重组商品再查，最多再查两轮；封面、规格图少了会影响商品，只提示；保留的图不问、不去掉。
- 挑出的问题带编号（先文案、后图）写进商品稿的「说明」，图写图的名字（「主图 2」「详情图 3」「规格图：黑貓・浴水生財」），不写图片 id；印在商品上的、保留的图不写。不进收件箱。
- 文案、规格名的问题：写文案的 agent 只改我们自己文案里真有的简体字、错字，改一次就停；从图上引出来的意见（图上的字和文案对不上、措辞、尺寸标注）不为它改文案，留在说明里，人审稿时想看再看。
- 图的名字是传好的图的排号：人删了的、x2 去掉的也占着号，别的图的名字不跟着变（重做商品稿重新排）。
- 保留的图：x2 去掉的图人说要用，agent 用 `x2 listing keep <商品稿> <主图 N、详情图 N…>` 放回来，记进「保留的图」（人定的），以后检查再挑它也不去掉。人删的图（已删除的图）不放回来。

## 建商品、上架

- 在卖家中心的页面里发 `create_product_info`（从别处发会被反爬拒）。`product_info` 的格式在 `src/listing/product.ts`。物流渠道照卖家中心的样子：有尺寸的渠道 `sizeid` 是 1，填错回 1000100256。
- 先建成下架，读回来逐项核对（标题、货号、类目、重量、主图、尺码表、备货天数、物流、描述里的字和图、每个规格的选项、价格、库存），对上了才上架；上架以后读回来状态是在售才算。对不上就停在下架，给人看。
- 1000100256 是字段校验失败（缺必填属性、详情图尺寸、缺尺码表……），不是重复：响应里全部的 `Rule Type` 写进写入的原因。
- 建商品结果未知：不重发，按货号在全部商品里找；找不到请人到卖家中心看。
- 店铺被限制（新增商品页跳到「權限不足 / 賣場遷移中」）：停下，要人处理。人可以在店铺设置的「暂停上品原因」里写原因。
- `x2 run` 先按检查的规则重算勾了「批准上架」的商品稿（去掉内容变了的勾），给勾着的生成写入；执行完（成功、被拒、不一致、结果未知都算）马上重算这几份商品稿的当前步骤、说明，不读站点；收件箱等下一次 `x2 status` 重算。

## 策略

选品由 agent 定策略、做实验（explore / exploit）。「策略」表一行一个：假设（押什么）、选品方法（怎么选）、状态（试验中 / 使用中 / 已停用）、版本号。每份商品稿记下它从哪个策略来（人贴的是「人选」）。策略只写通用的做法，不写具体的东西：一次用哪个种子（例 硅藻泥地垫）、哪个节日（例 万圣节）、哪些词，写进那几份商品稿的「依据」，不另开策略。

每份商品稿能回头查为什么选、按的是哪一版策略和规矩：

- 策略的版本号：`x2 strategy add` 是第 1 版，`x2 strategy set` 每改一次加 1，「策略变更记录」记一行（改之前、改之后、理由、变更时间）。`set` 必须写 `--why`；和现在一样的不算改。
- 选品规矩：所有策略共用的规矩（例 1688 一件代发、48 小时发货、起订量 1），一行一条，有理由。不用了就停用（写结束时间、停用原因），不删。
- 商品稿的「选品理由」（为什么选它，一两句）、「依据」（台湾的热搜词和搜索量、竞品价格和销量、1688 月销、报价……）、「选品快照」（加进来那一刻的策略：名字、版本号、假设、选法；在用的选品规矩：编号、内容；时间）。按策略选的，`x2 listing add` 必须写 `--why`；几个链接一起加的理由是同一份。已经有的商品稿再加不改。
- 补记：`x2 listing why` 给已经加进来的商品稿写理由、依据。没有选品快照的照现在补一份，标明补记（`backfilled`，时间是补记的时间）；有的不动。已有理由的要 `--force` 才覆盖，输出里写着覆盖了什么。

选品时先报价，再决定添不添这个货源：`x2 listing quote <1688 链接或货源 id> [--shop 店]` 读货源、排规格、按这家店的店铺设置核价（和做商品稿同一套代码，不做图、不存库），回售价区间、每个规格的价格和重量、服务（一件代发、48 小时发货）、起订量、用的国内运费、问题。1688 没给的重量按 `--weight` 算（默认 1 kg）、读不到的国内运费按 `--freight` 算（默认 10 元），往重了、往高了估，用了估的写出来。读 1688 照样排队、隔几秒，报一批货源别连着刷。

```
x2 strategy add <名字> --bet "假设" --how "选品方法" [--why "…"]   第 1 版
x2 strategy set <名字> --why "…" [--status 使用中|已停用|试验中] [--bet …] [--how …] [--note …]
                                      改状态，或者边试边改假设、选法：版本号加 1，记进变更记录
x2 strategy list                      每个策略第几版、出了几份商品稿、上架了几个
x2 strategy log <名字>                 这个策略的变更记录
x2 rule add "<规矩>" --why "…"          记一条选品规矩
x2 rule retire <编号> --why "…"         停用（不删）
x2 rule list [--all]                  在用的选品规矩（--all：连停用的）
```

还没做的：按策略汇总上出来的商品的曝光、点击、加购、订单、毛利（等有商品上架了，照 Shopee 的商品表现做）。
