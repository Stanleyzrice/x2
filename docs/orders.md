# 订单（草稿）

读者是推进订单的人和 agent。这份讲一张订单从进来到仓老板「已打包」要做哪些事、每一步怎样算做完、谁做；以后加上售后、退件、结算（参照 lilto 的 `docs/requirements/orders.md`：订单这个主题从买家下单开始，到收款和对账完成结束）。x2 怎么一轮一轮推进在 [loop.md](loop.md)，每个词的意思在 [glossary.md](glossary.md)。

## 现在的流程（运营讲的，2026-10-09）

例：Shopee 来了两张订单，订单 1 买红T ×1，订单 2 买红T ×2。仓老板是货代。

1. **订单进来。** 仓老板自动出现同一个订单号的订单，仓老板状态「待处理」（站上的代码是 paid，卡片上写「订单状态：已付款」）。两家店的订单都在仓老板里。
2. **加购。** agent 把 3 件红T加进 1688 购物车，记下加在哪个 1688 账号。
3. **付款。** 人在那个账号的购物车里付款，付完在 agent 里说「我付好了」（或者用 skill）。agent 对采购单（见下一节），知道哪几张订单付了、寄到了哪。不说也行，下一轮 `x2 status` 也会看到。
4. **预报**，付完款再报。1688 寄到哪，预报就跟着不一样：

| | 寄到我们这里（大部分） | 寄到仓老板 |
|---|---|---|
| 预报 | 付完款就报：发货线路选「海快」（752），点「无单号」 | 等 1688 发货、有了快递单号再报：发货线路选「海快」，每个商品填快递单号和件数；几张订单的货在同一个快递里，勾「复用」 |
| 货到了以后 | 打包：人拆开 3 件红T，按订单重新打包（订单 1 一件、订单 2 两件），在仓老板上打印「SKU 拣货单」贴上（一张订单一张，上面是订单号的条码、商品、件数），寄给仓老板 | 仓老板拆开，分给订单 |
| 变成「已打包」 | 仓老板扫描拣货单 | 仓老板打包 |

预报完仓老板状态是「已预报」（pre_report）。「已打包」（packaged）以后，已出库、运输中、已通关、已达目的仓库、分拣中、已派送，都是仓老板和 Shopee 的事（站上的代码都是 delivery）。

## 对采购单（旧文档里叫「认领」）

付完款，x2 读那个 1688 账号的采购单，按 1688 规格对加购（加购的写入记着每次是为哪张订单加的、加了几件），得出每张订单：

- 付了没：加购的货在采购单里了，不在购物车里了；
- 寄到哪：采购单的收货地址是我们这里，还是仓老板；
- 快递单号、签收了没：采购单的物流。

每轮现算，不另记一本账。结果用在三处：哪些订单可以预报；寄到仓老板的，预报填哪个快递单号；寄到我们这里的，哪张订单的货到齐了、可以打包。

人工分拣（收件箱里叫「打包」）是用这个结果的那一步，由人做；对采购单是 x2 自己算的。

## 每一步怎样算做完

| 一步 | 怎样算做完 | 谁 | 收件箱里写什么 |
|---|---|---|---|
| 选货源 | 每张没取消的订单，每个规格都有货源和 1688 规格 | agent 先自己找；找不到、拿不准才给人 | 选货源：红T 找不到对得上的 1688 规格（货源候选在「选货源」里） |
| 加购 | 没取消、货源齐了的订单都加过购 | agent 准备，人批准 | 批准：加购红T ×3（订单 1、2） |
| 付款 | 购物车里属于这些订单的货都付了 | 人，付完说「我付好了」 | 付款：1688 购物车里 2 张订单的货 ¥xx |
| 预报 | 付了款的订单都报了：寄到我们这里的报无单号；寄到仓老板的，有了快递单号就报 | agent 准备，人批准（跑顺了可以不批） | 批准：预报 2 张订单（海快、无单号） |
| 打包 | 寄到我们这里、货到齐了的订单，都在仓老板变成「已打包」 | 人（拣货单在仓老板上自己打） | 打包：2 张订单的货到齐了，每张装什么；只到了一部分的写「白T 到了，红T 还没到，先放着」 |
| 出货期限 | 每张订单在出货期限前「已打包」 | 人 | 快到期：订单 2 出货期限还剩 1 天，还没打包（卡在：没付款） |
| 取消 | 取消的订单：购物车里没有它的货；预报取消了；已经买了的货有去处 | agent 准备取消预报，人批准；其余人做 | 取消：订单 1 取消了，红T ×1 在购物车里，删掉 |
| 问题单 | 仓老板上没有问题单 | 人 | 问题单：订单 X 在仓老板标了问题 |

**选货源**：缺货源时 agent 先自己找（现在的 `x2 buy source` 已经会，以后叫 `x2 source`）：先看这个商品别的规格用的货源，在里面找名字对得上的 1688 规格；没有再拿商品图经知虾以图搜图。规格名里的数字、颜色都对得上，而且只有一个对得上的，直接用：批准加购时每一行写着哪个货源、哪个 1688 规格，带图，人批准了加购，这个货源才写进规格。对不上，或者几个都像，才进收件箱。一张订单里有规格缺货源，这张订单先不加购，等人选好。

**快到期**写出卡在哪一步：没货源、没加购、没付款、没预报、货没到齐（还差哪件）、到齐了没打包。

**货到齐**：一张订单的几件商品常常从几家买、分几个包裹到，对采购单得出它们全签收了才算到齐，才能打包。

## 要人配置的（NocoDB 的「订单设置」）

- 发货线路：海快（752）。
- 仓老板的收货地址：x2 用它认出哪些采购单是寄到仓老板的。
- 预报要不要批准：先要；跑顺了关掉。
- 快到期：出货期限前几天提醒。

## 已经定了的
