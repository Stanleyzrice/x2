# 订单（草稿）

读者是推进订单的人和 agent。这份讲一张订单从进来到 chanboss「已打包」要做哪些事、每一步怎样算做完、谁做；以后加上售后、退件、结算（参照 lilto 的 `docs/requirements/orders.md`：订单这个主题从买家下单开始，到收款和对账完成结束）。x2 怎么一轮一轮推进在 [loop.md](loop.md)，每个词的意思在 [glossary.md](glossary.md)。

## 现在的流程（运营讲的，2026-10-09）

例：Shopee 来了两张订单，订单 1 买红T ×1，订单 2 买红T ×2。chanboss 是货代。

1. **订单进来。** chanboss 自动出现同一个订单号的订单，chanboss 状态「待处理」（站上的代码是 paid，卡片上写「订单状态：已付款」）。两家店的订单都在 chanboss 里。
2. **加购。** agent 把 3 件红T加进 1688 购物车，记下加在哪个 1688 账号。
3. **付款。** 人在那个账号的购物车里付款，付完在 agent 里说「我付好了」（或者用 skill）。agent 对采购单（见下一节），知道哪几张订单付了、寄到了哪。不说也行，下一轮 `x2 status` 也会看到。
4. **预报**，付完款再报。1688 寄到哪，预报就跟着不一样：

| | 寄到我们这里（大部分） | 寄到 chanboss |
|---|---|---|
| 预报 | 付完款就报：发货线路选「海快」（752），点「无单号」 | 等 1688 发货、有了快递单号再报：发货线路选「海快」，每个商品填快递单号和件数；几张订单的货在同一个快递里，勾「复用」 |
| 货到了以后 | 打包：人拆开 3 件红T，按订单重新打包（订单 1 一件、订单 2 两件），在 chanboss 上打印「SKU 拣货单」贴上（一张订单一张，上面是订单号的条码、商品、件数），寄给 chanboss | chanboss 拆开，分给订单 |
| 变成「已打包」 | chanboss 扫描拣货单 | chanboss 打包 |

预报完 chanboss 状态是「已预报」（pre_report）。「已打包」（packaged）以后，已出库、运输中、已通关、已达目的仓库、分拣中、已派送，都是 chanboss 和 Shopee 的事（站上的代码都是 delivery）。

## 对采购单（旧文档里叫「认领」）

付完款，x2 读采购账号的采购单，按 1688 规格对加购（加购的写入记着每次是为哪张订单加的、加了几件），得出每张订单：

- 付了没：加购的货在采购单里了，不在购物车里了；
- 寄到哪：采购单的收货地址是我们这里，还是 chanboss。采购单列表里没有收货地址（2026-10-09 核对过）；1688 的默认地址就是我们这里（东莞，收件人写「1971张」，1971 是我们在 chanboss 的客户号），所以都当成寄到我们这里；
- 快递单号、签收了没：采购单每一行的状态（已发货、已收货）、已收件数和物流。

对完加购以后剩下的采购单，再按 1688 规格分给还没付款的订单行（先下单的先分）：这是在 x2 外面买的（人直接在 1688 上买，或者 x2 加了购、人又另外买了一份）。分到的订单算付过了，接着预报；x2 加进购物车的那一份标成「不该买：已经在外面买了」。只有一个采购账号，这个账号买的每一件 x2 都看得到，才能这样推断；规格没有货源的，对不上。

每轮现算，不另记一本账。结果用在三处：哪些订单可以预报；寄到 chanboss 的，预报填哪个快递单号；寄到我们这里的，哪张订单的货到齐了、可以打包。

人工分拣（收件箱里叫「打包」）是用这个结果的那一步，由人做；对采购单是 x2 自己算的。

## 每一步怎样算做完

| 一步 | 怎样算做完 | 谁 | 收件箱里写什么 |
|---|---|---|---|
| 选货源 | 每张没取消的订单，每个规格都有货源和 1688 规格 | agent 先自己找；找不到、拿不准才给人 | 选货源：红T 找不到对得上的 1688 规格（货源候选在「选货源」里） |
| 加购 | 没取消、货源齐了的订单都加过购 | agent 准备，人批准 | 批准：加购红T ×3（订单 1、2） |
| 付款 | 购物车里属于这些订单的货都付了 | 人，付完说「我付好了」 | 付款：1688 购物车里 2 张订单的货 ¥xx |
| 预报 | 付了款的订单都报了：寄到我们这里的报无单号；寄到 chanboss 的，有了快递单号就报 | agent 准备，人批准（跑顺了可以不批） | 批准：预报 2 张订单（海快、无单号） |
| 打包 | 寄到我们这里、货到齐了的订单，都在 chanboss 变成「已打包」 | 人（拣货单在 chanboss 上自己打） | 打包：2 张订单的货到齐了，每张装什么；只到了一部分的写「白T 到了，红T 还没到，先放着」 |
| 出货期限 | 每张订单在出货期限前「已打包」 | 人 | 快到期：订单 2 出货期限还剩 1 天，还没打包（卡在：没付款） |
| 取消 | 见下面「买家取消」 | 人；预报 agent 取消 | 取消：订单 1 取消了，购物车里还有 1 件，删掉 |
| 问题单 | chanboss 上没有问题单 | 人 | 问题单：订单 X 在 chanboss 标了问题 |

**选货源**：缺货源时 agent 先自己找（现在的 `x2 buy source` 已经会，以后叫 `x2 source`）：先看这个商品别的规格用的货源，在里面找名字对得上的 1688 规格；没有再拿商品图经知虾以图搜图。规格名里的数字、颜色都对得上，而且只有一个对得上的，直接用：批准加购时每一行写着哪个货源、哪个 1688 规格，带图，人批准了加购，这个货源才写进规格。对不上，或者几个都像，才进收件箱。一张订单里有规格缺货源，这张订单先不加购，等人选好。

**快到期**：离出货期限不到 6 天（订单设置里改）、还没「已打包」，直接进收件箱给人，写出卡在哪一步。卡在哪一步是固定的几步（看板按它分列）：没货源、没加购、加购等批准、没付款、没预报、预报等批准、货没到齐、到齐了没打包、等 chanboss 收货、等 chanboss 打包、不是经 x2 买的、已打包、取消了；细节（还差哪件、哪个规格没货源）另放一列。

**货到齐**：一张订单的几件商品常常从几家买、分几个包裹到，对采购单得出它们全签收了才算到齐，才能打包。

## 异常

订单大部分的状态在 chanboss 上跟踪。下面是从订单进来到「已打包」中间会出的岔子，每一种怎么发现、谁处理、x2 怎么知道处理完了。x2 看得到结果的，收件箱那一行自己关；看不到的，人做完在收件箱勾「处理好了」。

| 异常 | x2 怎么发现 | 谁处理、怎么处理 | 怎么算处理完 |
|---|---|---|---|
| 没货源、货源失效（下架、没这个规格、库存不够、涨价超过 10%） | 检查；加购前现读货源 | agent `x2 source` 找，拿不准的人在「选货源」里勾 | 规格有了货源 |
| 在 x2 外面买了（只有一个采购账号时，是人直接在 1688 上买的） | 对采购单：对不上加购的采购单分给还没付款的订单 | 不用做：算付过了，接着预报；x2 加进购物车的那份标「不该买」 | 采购单对上了 |
| 加购时撞上（准备加购到执行之间，人已经买了或加了购） | `x2 run` 加购前现读采购账号的购物车和采购单，再对一次 | x2 不加，写明原因 | — |
| 加购结果未知 | `x2 run` | x2 读回来；还看不出的人到 1688 购物车看，在「写入」里改成已核对或被拒 | 写入有结果 |
| 1688 没发货、采购单关闭 | 采购单状态（交易关闭的不算付过） | 人换货源，x2 重新准备加购 | 新的采购单对上了。没发货多久算异常还没定 |
| 错货、少件、坏了 | x2 看不到：打包的人在 NocoDB 的表单「报到货问题」里填（订单号、哪件、什么问题、几件） | 人找 1688 卖家退换，或者重新买；没处理好之前这张订单卡在「到货有问题」，不提醒打包 | 人在「到货问题」里勾「处理好了」。重新买还是人去买（以后可以让 x2 准备加购） |
| 快到期 | 不到 6 天、还没打包 | 人（收件箱写出卡在哪一步） | 已打包 |
| 过了出货期限 | Shopee 自动取消 | 同「买家取消」 | — |
| 问题单 | chanboss 标了问题 | 人 | 问题单消了 |

### 买家取消

看货走到了哪：

| 货在哪 | x2 怎么认 | 怎么处理 | 怎么算处理完 |
|---|---|---|---|
| 还没加购 | 没有加购、没有采购单 | 不用做 | — |
| 在购物车里 | 购物车 | 删掉 | 购物车里没了（x2 看得到） |
| 付了款，1688 还没发货 | 采购单这一行是待发货 | 在 1688 申请退款 | 勾「处理好了」（**缺口**：还没读退款状态） |
| 1688 发了货，没到 chanboss（路上、在我们这里） | 采购单这一行是已发货、已收货 | 退回 1688 卖家 | 勾「处理好了」（同上） |
| 在 chanboss 仓库（chanboss「已到齐」） | chanboss 状态 | 给新订单用（合并发货），或者退回卖家 | 勾「处理好了」 |
| 到了台湾（chanboss「已打包」以后） | chanboss 状态 | 在 chanboss 台湾仓上架，30 天内给别的订单用；过了 30 天货代会处理掉，货就没了 | 用掉了勾「处理好了」；过了期限自己关（货没了，这件事也就结束了）。期限先按取消的时间 + 30 天；读到 chanboss 的上架时间以后按上架时间算 |
| chanboss 上还挂着预报 | chanboss「已预报」 | 不重要：agent 去取消（x2 还不会取消预报，先不管） | — |

例：260917A6PM8V15（衣帽架）9/17 下单，crystal 9/20 在她的账号买了，9/30 x2 又往另一个账号加了一件进购物车，10/7 买家取消。现在要：删掉购物车里那件；已经收到的那件退回 1688 卖家。

## 要人配置的（NocoDB 的「订单设置」）

- 采购账号：只有一个账号做采购，x2 只往它加购，别的 1688 账号只读。现在是 crystal 的（会员名「桥头等白马」）；换账号改这一格。
- 发货线路：海快（752）。
- chanboss 的收货地址：x2 用它认出哪些采购单是寄到 chanboss 的。现在都寄到 1688 的默认地址（我们这里），用不上。
- 预报要不要批准：先要；跑顺了关掉。
- 快到期：离出货期限不到几天、还没打包就给人（6 天）。

收件箱的「谁做」照「谁做」那张表填（现在都是运营）。以后采购、财务分开，改那张表，在 NocoDB 里按「谁做」各建一个视图。

## x2 要做的

| | 代码 |
|---|---|
| 订单 | 用 chanboss 的订单列表（两家店都在，带商品、出货期限、平台状态、chanboss 状态）：`x2 sync orders`。加购、预报前现读 chanboss 核对还是待出货、还是待处理（两家店都在里面，不用开那家店的浏览器） |
| 选货源 | `x2 source`：agent 自己找（这个商品用过的 → 以图搜图 → 按规格名打分），明显对得上的随加购一起批准；拿不准的写成货源候选，人在 NocoDB 的「选货源」里勾 |
| 加购 | 加购这个写操作：同一个 1688 规格的几张订单合成一行，经 `x2 propose` 写成待批准；批准后 `x2 run` 一个规格一个规格加，前后读购物车核对；记下加在哪个 1688 账号 |
| 付款、到货 | `x2 sync cart purchases`（购物车、采购单和物流），检查里对采购单。采购单的收货地址、物流的字段还没有真数据核对过：第一次真付款以后核对 |
| 预报 | chanboss 的预报（寄到我们这里 = 海快 + 无单号；寄到 chanboss = 海快 + 每个商品的快递单号、件数）：请求体照页面的 JS 拼好了，没在真订单上跑过（`x2 run --try 预报`）；几张订单共用一个快递的「复用」还没做。取消预报还没有：先在页面上点一次看它发到哪 |

## 已经定了的

运营答过的（2026-09-29，lilto）：不采购就是不选，不用标记；加购、付款都由人；退件分给哪张订单由 agent 提议、人定；广告费按「店铺 × 天」看，不摊到每单。

2026-10-09：付完款再预报；付款由人在 agent 加购的那个 1688 账号里付，付完说「我付好了」；缺货源时 agent 先自己找，找不到才进收件箱；chanboss 的「自动预报」先不管；拣货单由人在 chanboss 上自己打。

2026-10-09（晚）：只有一个采购账号（现在是 crystal 的），但要能对付「有人在 x2 外面买了」；快到期 = 不到 6 天还没打包，直接给人；订单取消以后 chanboss 上的预报不重要，agent 取消就行；chanboss「已到齐」是货到了 chanboss 的仓库，「已打包」以后算到了台湾；取消的订单的货能合并给新订单用（例 260818N3M465ST、260907DMD3ERJ2 的地垫和 10/8 的新订单 2 + 7 件合并发货）。
