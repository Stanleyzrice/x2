# 订单

读者是推进订单的人和 agent。这份讲一张订单从进来到 chanboss「已打包」要做的事：每一步怎样算做完、谁做、出了岔子怎么办。x2 怎么一轮一轮推进在 [loop.md](loop.md)，每个词的意思在 [glossary.md](glossary.md)。

## 流程

例：订单 1 买红T ×1，订单 2 买红T ×2。

1. **订单进来。** Shopee 的订单出现在 chanboss 的订单列表里（同一个订单号），chanboss 状态「待处理」。列表要按日期查：页面上点「查询」，日期盖住最近这段时间；`x2 status` 每次按最近 60 天查。两家店的订单都在 chanboss 里。
2. **加购。** agent 把 3 件红T加进采购账号的 1688 购物车，记下每件是为哪张订单加的。人在终端里同意了才加。
3. **付款。** 人在采购账号的购物车里付款，付完说「我付好了」（不说也行，下一轮 `x2 status` 会看到）。
4. **预报。** 付完款才报：发货线路「海快」，「无单号」。不用 chanboss 的自动预报。
5. **打包。** 货到齐了，人拆开按订单重新装（订单 1 一件、订单 2 两件），在 chanboss 上打印「SKU 拣货单」贴上，寄给 chanboss。chanboss 扫拣货单，订单变成「已打包」。之后的已出库、运输中、已派送是 chanboss 和 Shopee 的事。

采购单都寄到 1688 的默认地址，就是我们这里。寄到 chanboss 的货不用我们打包，要等 1688 发货、有了快递单号再预报（每件填快递单号）。

## 采购单分给订单

1688 的采购单不记是为哪张订单买的：同一个货源的货一起付款，几张订单的货就在一张采购单里；一张订单的几样商品从几家买，又分在几张采购单里。x2 每轮把采购单分给订单，才知道每张订单买了没、到了没。

例：x2 给订单 1、2 一起加购了 3 件红T，记下「1 件给订单 1，2 件给订单 2」。付款以后 1688 出了一张采购单 P1：红T ×3。x2 按记下的把这 3 件分回去：订单 1 一件、订单 2 两件，两张都付了；P1 签收了，两张订单的红T都到了。

- **经 x2 加购的**：采购单里一个规格的件数，按加购的先后分给当初加购的订单。分到了就是付了；没分到的，购物车里还有就是还没付，购物车里也没有是「不见了」（人从购物车删了）。
- **不是经 x2 加购的**（人直接在 1688 上买的）：剩下的件数分给还没付款、缺这个规格的订单，先下单的先分；取消的订单只分它取消以前下的采购单。分到的算付过了；x2 给它加进购物车的那一份标「不该买」，付款前删掉。只有一个采购账号，它买的每一件 x2 都看得到，才能这样分。商品没有货源的分不到。
- **分到以后**，订单的这一件跟着那张采购单走：发货了没、快递单号、签收了没。一张订单的每件都签收了，才算到齐、能打包。

每轮从头分一遍，结果不存。用在三处：哪些订单能预报（付了）、哪些能打包（到齐了）、提醒人的「付款」「未发货」「取消」写什么。

## 每一步怎样算做完

| 一步 | 怎样算做完 | 谁 | 提醒人的、给人看的 |
|---|---|---|---|
| 选货源 | 每张没取消的订单，每个商品都有货源，店里的规格都在货源的规格里配得上 | agent 先找；拿不准才给人 | 选货源：红T 待人工选定；规格不匹配：红T / XL |
| 加购 | 没取消、货源齐了的订单都加过购 | agent 准备，人在终端里同意 | 加购：红T ×3（订单 1、2） |
| 付款 | 购物车里这些订单的货都付了 | 人，付完说「我付好了」 | 付款：1688 购物车里 2 张订单的货 ¥xx |
| 预报 | 付了款的订单都报了 | agent 准备，人在终端里同意 | 预报 2 张订单（海快、无单号） |
| 打包 | 货到齐了的订单都「已打包」 | 人 | 打包：订单 1 的货已到齐，装什么 |
| 出货期限 | 每张订单在出货期限前「已打包」 | 人 | 快到期：订单 2 出货期限剩余 1 天，未打包（当前步骤：待 1688 付款） |
| 取消 | 见「买家取消」 | 人；预报 agent 取消 | 取消：订单 1 已取消，购物车里还有 1 件待删除 |
| 问题单 | chanboss 上没有问题单 | 人 | 问题单：订单 X 被 chanboss 标记问题 |

**选货源**：店里一个商品只用一个货源。加购时按店里的规格名在货源的规格里配（数字、颜色都要对上，只有一个对得上才算）。缺货源时 agent 先找（`x2 source <商品 id>`，以图搜图，看卖过的规格有几成配得上）：卖过的规格都配得上、只有它这样的，人同意加购时一起定下；拿不准的提醒人「选货源」，人在网页「货源」里勾「选用」或贴链接（`x2 source <商品 id> --url <链接>`）。按名字配不上的规格提醒人「规格不匹配」：人定哪个配哪个，写在货源那一行的「规格例外」（「店里的规格名 = 货源的规格名」，或者告诉 agent 用 `x2 source <商品 id> --spec …` 写），或者换货源。缺货源、规格不匹配的订单先不加购。

货源存一份快照（标题、图、规格、价格），每次现读就更新，给人挑、比价。买之前一律现读；下架了标「不可用」，重新找。

**快到期**：离出货期限不到 6 天、还没「已打包」，提醒人，写出当前步骤。当前步骤（网页上订单按它分组）：缺货源、规格不匹配、待加购、待 1688 付款、待预报、待到齐、有到货问题、待打包、待 chanboss 收货、待 chanboss 打包、外部采购、已打包、已取消。

## 异常

x2 看得到结果的，处理完就不再提醒；看不到的，人说做完了，agent 用 `x2 handled <key>` 记下。

| 异常 | x2 怎么发现 | 谁处理、怎么处理 | 怎么算处理完 |
|---|---|---|---|
| 订单在 chanboss 里查不到 | 看不到 | 人在 chanboss 订单页「同步订单」，让它从 Shopee 重新拉 | 查得到了 |
| 缺货源、货源失效（下架、没这个规格、库存不够、涨价超过 10%） | 检查；加购前现读货源 | agent 找，拿不准的人选 | 有了货源 |
| 规格不匹配 | 按名字配不上，也没有规格例外 | 人定哪个配哪个，或者换货源 | 配得上了 |
| 外部采购 | 采购单分给订单时，有不是经 x2 加购的件数 | 不用做：算付过了；x2 加的那份标「不该买」 | — |
| 加购时撞上（人同意以后、执行以前人已经买了或加了购） | `x2 do` 加购前现读 1688 的购物车和采购单再分一次；读不全就不加 | x2 不加，写明原因 | — |
| 加购结果未知 | `x2 do`、`x2 verify` | x2 读回来；还看不出的人到 1688 购物车看，agent 用 `x2 resolve` 记成已核对或被拒 | 写入有结果 |
| 1688 未发货 | 付款 48 小时仍未发货 | 人催卖家；催不动就退款换一家，x2 重新准备加购 | 发货了，或新的采购单分到了 |
| 采购单关闭、退款成功 | 采购单状态 | 这几件不算付过，x2 重新准备加购 | 新的采购单分到了 |
| 错货、少件、损坏 | 打包的人在网页的表单「上报到货问题」里填 | 人找卖家退换或重新采购；处理完之前不提醒打包 | 人勾「已处理」 |
| 快到期 | 不到 6 天、还没打包 | 人 | 已打包 |
| 过了出货期限 | Shopee 自动取消 | 同「买家取消」 | — |
| 问题单 | chanboss 标了问题 | 人 | 问题单消了 |

### 买家取消

看货走到了哪：

| 货在哪 | x2 怎么认 | 怎么处理 | 怎么算处理完 |
|---|---|---|---|
| 还没加购 | 没有加购、没有采购单 | 不用做 | — |
| 在购物车里 | 购物车 | 删掉 | 购物车里没了 |
| 已付款，1688 未发货 | 采购单这一行待发货 | 在 1688 申请退款 | 退款成功（x2 读得到）；退款关闭是没退成，再提醒 |
| 1688 发了货，没到 chanboss | 采购单这一行已发货、已收货 | 退回 1688 卖家（退货退款） | 同上，提醒里写出退货走到哪一步 |
| 在 chanboss 仓库（「已到齐」） | chanboss 状态 | 合并给新订单，或者退回卖家 | 人说做完了（`x2 handled`） |
| 到了台湾（「已打包」以后） | chanboss 状态 | 在 chanboss 台湾仓上架，30 天内给别的订单用；过了 30 天货代处理掉 | 用掉了人说做完了（`x2 handled`）；取消 30 天以后不再提醒 |
| chanboss 上还挂着预报 | chanboss「已预报」 | agent 取消预报（还不会） | — |

## 订单设置（网页）

- 采购账号（1688 会员名）：x2 只往它加购，别的 1688 账号只读。
- 发货线路：海快。
- 快到期提醒（天）：离出货期限不到几天、还没打包就提醒（6）。
- 未发货提醒（付款后小时数）：1688 付款后几小时还没发货就提醒（48）。

## x2 的代码

| | 做到哪 |
|---|---|
| 订单 | `x2 status` 每次按最近 60 天查 chanboss 的订单列表，写回库（订单表）；加购、预报前再现读那几张 |
| 选货源 | `x2 source`：以图搜图、按规格名打分；`--url` 用人贴的，`--spec` 写规格例外 |
| 加购 | 写入：同一个规格的几张订单合成一行，人同意了 `x2 do`，前后读购物车核对 |
| 付款、到货 | `x2 status` 现读采购账号的购物车、采购单（带物流、进行中的退款），采购单分给订单。物流的字段还没在真付款以后核对过 |
| 预报 | 写入（海快 + 无单号，或海快 + 快递单号），还没在真订单上跑过（`x2 do --try 预报`）。几张订单共用一个快递的「复用」、取消预报还没做 |

## 售后、退件、结算（还没细化）

| 事 | 怎样算做完 | 代码 | 人 |
|---|---|---|---|
| 售后在期限前决定 | 每个没结束的售后在期限前有人决定 | 有 `shopee returns`；缺同意、拒绝 | 决定方案、金额 |
| 退件用起来 | 退件分给新订单 | 有 `chanboss returns`、`putaway` | agent 提议分给哪张订单，人定 |
| 已拨款的订单对得上 | 收入组成合计 = 净额 | 有 `income`、`income-components` | — |
| 每单利润 | 要采购成本、chanboss 的费用、货代账单 | | |
