读者是推进上品的 agent。命令在 x2 仓库根目录运行：`node bin/x2.ts <命令>`（下面简写成 `x2`），加 `--json` 读结果。每一步怎样算做完、规矩从哪来在 [docs/listing.md](../../../docs/listing.md)。

## 步骤

1. **`x2 status --json`**：看 `todo` 里的「做商品稿」「写文案」「Gemini 文字检查」「上架」，`inbox` 里类别是「商品稿」的（待补充的）。`x2 listing list` 列出每份商品稿的当前步骤。
2. **添加货源**：运营给了 1688 链接，`x2 listing add <店> <链接…>`（店是 `ni1206` 或 `cheeroutdoor`）；按策略选出来的加 `--strategy <名字>`（先 `x2 strategy add` 记下这个策略）。两家店各卖各的：同一个货源别两家都上，除非运营说。运营也可以在 NocoDB「商品稿」的「添加货源」表单里贴。
3. **做商品稿**：`x2 listing make [商品稿…]`。一份要几分钟：每张图 Gemini 看一次，有简体字的交象寄译成繁体（收费，一张约 0.025 元），译好的再查一遍（还有简体字、商品上的字被改了的不用），加本店水印，传 Shopee；再定类目、属性、备货天数，按店铺设置核价。做完它会说哪些待补充（重量、国内运费、类目不在本店范围、要填字的属性）：请运营在 NocoDB「商品稿」里填，填好了再 `x2 listing make`。
4. **写文案**（标题、描述、规格名）：能开 subagent 就交给 `listing-copy`（给它商品稿编号；它读规矩、写、交给 x2、照 Gemini 文字检查挑出的问题改，回报结果），主对话不用装每份商品稿的事实。自己写的话：`x2 listing show <商品稿>` 看事实（货源标题、规格的每层和每个选项、类目、属性、服务），照 docs/listing.md「文案」写台湾繁体的标题、描述和规格名：
   - 标题 10–60 字（含空格），核心品名放最前：「核心品名＋关键差异＋用途场景＋款式选择」，资料够时 55–60 字；
   - 描述按「商品介紹、規格選擇、使用提醒」分段，最多 3000 字；
   - 只用给的事实：不编造品牌、材质、认证、功能、产地、赠品、热销、免运、发货时效；不写价格；随机款写明随机；不把不同规格的属性写成每件都有；
   - 不写厂家、批发、代发、冲量、定制、爆款这类话；两家店的标题不能一样；
   - 规格名：每层的层名、每个选项的名字，个数、顺序照 show 的 `tiers`，规矩在「文案」。
   写好用 `x2 listing text <商品稿> --title … --description … --tiers '[{ "name": "款式", "options": […] }, …]'`（几份一起：`x2 listing text < [{ id, title, description, tiers }]`）；有一样不对就什么都不存，照它说的改了再交。写完马上 Gemini 文字检查：只提示、不挡，挑出的问题带编号写进商品稿的「说明」。文案、规格名的问题照着改，再交，最多两次；改不掉的、像误报的（把繁体当成简体）不用管，人审稿时看。图的 x2 自己处理：印在商品上的字不算问题，详情图、不是封面的主图上后加的文案 x2 去掉。
5. **上架**：`todo` 里「上架」那一项的 `propose` 原样交给 `x2 propose`。告诉运营去 NocoDB「商品稿」的「审稿」画廊看：标题、主图、详情图、规格和价格、规格图；不要的图在「主图」「详情图」里删掉附件（删了图要再查一次，`x2 status` 会说）；「说明」里有 Gemini 挑出的问题。她说 x2 去掉的哪张图要用（说明里写着「x2 已去掉」，例 详情图 3），`x2 listing keep <商品稿> 详情图 3` 放回来（记进「保留的图」）。运营说哪个规格不要（例 接不了的「定製」），`x2 listing drop <商品稿> <选项名…>` 去掉整个选项（两层有同名的写「层名:选项名」，单个规格写货号；去掉单个规格会让两层的组合不齐时它不做，要么去掉整个选项，要么她说了才加 `--merge` 合成一层「款式」），再 `x2 listing audit <商品稿>`。她在收件箱勾「批准」（或在终端里说「批准」，你用 `x2 approve <批次>`），运行 `x2 run`。
6. **`x2 run`**：建商品（先建成下架）→ 读回来逐项核对 → 上架 → 读回来在售。把每一行的结果原样告诉她。「不一致」是读回来和提交的对不上：商品停在下架，请她到卖家中心看，在「写入」里改成已核对（没问题）或被拒。

## 规矩

- 上哪些货源、批不批准是运营定的；你准备、写文案，不替她定。数（售价、重量、国内运费）由代码算，你不改。
- 店铺设置（核价参数、水印、允许的类目、暂停上品）是人定的，人让你改才改。
- 保留的图（`x2 listing keep`）要运营说了才用。
- 退出码 3（没登录、要过滑块、浏览器没连上、店铺被限制）：请运营在浏览器里处理，再重试。退出码 4（结果未知）不重试：`x2 run` 下次会先读回来。
- 命令报错，把原话告诉运营。
