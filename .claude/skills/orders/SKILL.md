读者是推进订单的 agent。命令在 x2 仓库根目录运行：`node bin/x2.ts <命令>`（下面简写成 `x2`），加 `--json` 读结果。订单的每一步怎样算做完在 [docs/orders.md](../../../docs/orders.md)。

## 步骤

1. **`x2 status --json`**：看 `inbox`（人要做的）和 `todo`（你能做的）。按出货期限从近到远跟运营说：几张订单、各卡在哪一步（订单上的 `step`）；快到期的先说。
2. **找货源**（`todo` 里有「找货源」）：运行它给的 `x2 source <商品…>`（参数是店里的商品 id）。一个商品只用一个货源：它拿商品图以图搜图（要知虾登录着），看店里卖过的规格在每个货源里有几成配得上：
   - 卖过的规格都配得上、只有它这样：标成明显对得上，随加购一起批准，不用问人；
   - 拿不准的：写进「货源」，收件箱多一行「选货源」。告诉运营去 NocoDB 的「选货源」里勾「用这个」。她贴了 1688 链接，用 `x2 source <商品 id> --url <链接>`。
   不替运营选。货源定了、店里某个规格配不上，收件箱会有「规格对不上」：请她改店里的规格名，或者换货源。
3. **加购**（`todo` 里有「加购」）：把那一项的 `propose`（`{ title, writes }`）原样交给 `x2 propose`（从 stdin 读）。先看一眼：每一行是哪个货源、货源的哪个规格、几件、哪几张订单，带「（新货源）」的是这次一起批准的货源。告诉运营收件箱里有一行「批准：加购……」；她勾了批准（或在终端里说「批准」，你用 `x2 approve <批次>`），运行 `x2 run`，把每一行的结果原样告诉她。
4. **付款**：人在收件箱「付款」那一行写着的 1688 账号的购物车里付款。「不该买」的（订单取消了、已经打包了）提醒她付款前删掉。她说「我付好了」：运行 `x2 status`（现读购物车和采购单），说哪几张订单付了、寄到哪。
5. **预报**（`todo` 里有「预报」）：同第 3 步，交给 `x2 propose`。寄到我们这里的报海快、无单号；寄到 chanboss 的等 1688 发货、有了快递单号才会出现。预报还没在真订单上跑过：`x2 run` 会说要 `--try 预报`。第一次和运营约好一张单，一起跑 `x2 run --try 预报`，跑完请她在 chanboss 上看一眼对不对。
6. **打包、快到期、取消、问题单**：都是收件箱里人要做的。照那一行的详情告诉运营（打包：哪张订单装什么，在 chanboss 上打 SKU 拣货单；取消：购物车里删什么、货退款还是退回卖家、台湾仓的货 30 天内用掉）。x2 看不到结果的（退款、退货、合并、台湾仓），请她做完在收件箱勾「处理好了」。取消的订单在 chanboss 上的预报不重要，不用请人去取消。

## 规矩

- 改站点只经 `x2 propose` → 批准 → `x2 run`；不自己发请求。`x2 propose` 只收检查算出来该做的：它说「现在不该……」时，先 `x2 status` 看为什么。
- 结果未知（退出码 4）不重试：`x2 run` 下次会先读回来；还核不清的，请运营去站点上看，在「写入」里改成已核对或被拒。
- 退出码 3（没登录、要过滑块、浏览器没连上）：请运营在浏览器里处理，再重试。
- 命令报错，把原话告诉运营，不自己改库里的数据。
